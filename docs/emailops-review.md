# EmailOps: разбор похожего проекта (2026-10-23)

[EmailOps](https://getemailops.com/en/) ([github.com/emailops/emailops](https://github.com/emailops/emailops)) — десктопный почтовый клиент с локальным ИИ на том же стеке, что у нас: Rust, Tauri 2, SQLite с FTS5 и sqlite-vec; фронт на React. Один разработчик, Apache-2.0, ~1200 коммитов, 34 звезды на 23.10.2026. Ценность для нас не в коде, а в трёх документах репозитория: `docs/DECISIONS.md` (журнал решений с датами, причинами и отвергнутыми вариантами), `docs/COMPETITOR-PARITY.md` (аудит против Gmail и Outlook) и `docs/IMPLEMENTATION-GAPS.md` (список ~50 собственных дыр с приоритетами).

## 1. Где расходимся

- **Транспорт.** Gmail API, Microsoft Graph и IMAP/SMTP. Exchange через OWA JSON или EWS нет; по их же аудиту Outlook-путь самый слабый (запись статусов локальная, нет списка папок, `Retry-After` обрезан до 30 с). Для `aiowa-transport-owa` брать нечего.
- **Масштаб.** Они проектируют под десятки тысяч писем (упоминают 47k и ящик 6 ГБ), мы — под 450 тыс.–1 млн и 100 ГБ (CONCEPT §6). Их brute-force по векторам без партиций нам не подходит.
- **Язык.** en/es/fr/de; списки ключевых слов маршрутизатора только en/es. Русская морфология, транслит, словарь имён (CONCEPT §5.1) остаются нашими.
- **Позиционирование.** Строго локальный ИИ, облачный вариант «вне scope». У нас режим A и шлюз моделей (CONCEPT §5.6).
- **UI.** React + Zustand + Tailwind против Svelte 5. Код не переносится, паттерны — да.

## 2. Что брать

### Этап 1, ядро чтения и текущий UI

- Горячие клавиши из одной таблицы (чистый матчер, оверлей `?` рендерится из неё же). Любой диалог/меню/поповер регистрируется, и пока открыт хоть один, клавиши списка не срабатывают; тест ловит незарегистрированные оверлеи. Повод: контрибьютор клавишей Delete удалил беседу за открытым диалогом.
- Авто-переход к следующей беседе после архива/удаления/snooze (дефолт Outlook); настройка «предыдущая / назад к списку».
- Уведомления о новой почте решает бэкенд в конце инкрементального sync, после фильтров спама; 1–3 письма по отдельности, дальше сводка, не чаще раза в минуту на аккаунт; `Notifier` как trait, чтобы тесты не трогали ОС.
- Окно отмены: архив и удаление ждут 6 с до вызова сервера, потому что откат после вызова потребовал бы трёх путей восстановления. Принцип: у каждого необратимого действия есть достижимая обратная кнопка.
- Их список из 13 must-have для паритета с Gmail/Outlook как сверка нашего критерия «10 дней без браузерной OWA»: архив, «не прочитано», флаг, мультивыбор и массовые действия, отмена архива/удаления, отмена отправки, отложенная отправка, snooze, подпись на аккаунт, клавиши, отписка в один клик, блокировка отправителя, уведомления. У нас многое из этого серверное (флаг, категории, правила), локальные обходы для IMAP не нужны.

### Этап 1, движок синхронизации (их баги как чеклист)

- Неудачная загрузка не должна защёлкивать «бэкфилл завершён»; отчёт «X из Y, Z не удалось» с сохранением id неудачных; sync обязан громко падать на ошибке БД и персистить состояния `syncing/idle/error`.
- Прерванный sync оставлял статус `syncing` до рестарта; дедуплицированные ошибки не давали терминального события — спиннер и заблокированная кнопка «обновить» навсегда.
- Кассеты мок-серверов провайдеров для интеграционных тестов (большой первый sync, частичные сбои пачки, протухание delta-токена, переименование папок, backoff). Наш аналог — харнесс на фикстурах спайка OWA JSON.
- Неиндексированные FK-колонки и `message_id` → полные сканы и затыки на удалениях под блокировкой; `IN (?, …)` не длиннее лимита SQLite 32 766 параметров; `%infix%` только через FTS5; `OR` разбивать на `UNION` CTE.

### Этап 3, операции записи

- Статус «прочитано» ставится локально сразу, пуш на сервер с пометкой pending и повторами (до 100 строк, не старше недели). Обновление с сервера не трогает строки с ожидающим пушем. Черновики с локальными правками побеждают серверные, удалённые пересоздаются.
- Отмена отправки и отложенная отправка — одна локальная таблица `outbox`; переход `scheduled → sending` одним защищённым UPDATE, чтобы не было двойной отправки; строка, застрявшая в `sending` после краха, становится `failed` и не переотправляется сама.
- Отписка только по явному действию (RFC 8058 one-click → mailto → https), заголовки перечитываются бэкендом, страницы не фетчатся молча — это подтверждает адрес трекерам.

### Безопасность и Windows

- Учётные данные не пересекают IPC: бэкенд отдаёт только `hasPassword`, у структур с секретами ручной `Debug` (у нас так же, `aiowa-transport::Credentials`).
- Windows Credential Manager режет значение около 2,5 КБ; у них из-за этого сломался второй аккаунт, лечится нарезкой на несколько записей. Мы храним только пароль, но если положим cookies и canary сессии OWA — упрёмся.
- Переполнение стека очереди задач Tokio на Windows: футуры боксируются до await, стек задачи 8 МиБ.
- Сырые ошибки библиотек, пути и SQL не доходят до webview; каждая команда проверяет принадлежность записи активному аккаунту; CSP с `srcdoc`-iframe и allowlist-санитайзером; файлы вложений получают метку карантина ОС, опасные типы — подтверждение.

### Этапы 2 и 4, ИИ-слой

- Гибридный поиск FTS5 + sqlite-vec (768d) + RRF подтверждает CONCEPT §5.1.
- Цитаты ссылками `email://ID`, не номерами: модель сама нумеровала пункты, и `[n]` открывал чужое письмо (3 → 0 ошибок на 53 кейсах). Наши чипы `[msg:ID]` в §5.2 — в ту же сторону, номера не использовать вовсе.
- Списки и счётчики считает код: «счёт маленькой модели — догадка». Классификатор выбирает список / счёт / анализ, в LLM уходит только анализ.
- JSON под грамматикой: GBNF на llama.cpp, JSON Schema на Ollama, strict `response_format` у облака; свободный текст обрезался посреди пачки незаметно.
- Теги ранжируют, но не фильтруют (жёсткий фильтр спрятал счета); маршрутизация — подсказка, что доставать, а не отбор инструментов; попадание по ключевому слову бесплатно, промах — к планировщику.
- Дедупликация цитат в треде: блок выбрасывается, только если ~80 % его пятисловных отрезков уже встречались выше (доля прочитанного 31 % → 66 % на 50 письмах). Готовый алгоритм для «единой функции извлечения текста» из `pseudonymization-design.md` §3.1.
- KV-кэш префикса: неизменная голова промпта кэшируется (планировщик 1161 → 495 мс), одноразовые вызовы идут на отдельном слоте, всё переменное на ход вынесено за префикс и закреплено тестом. CONCEPT §5.4 говорит «на prompt caching не полагаться» — для vLLM на GPU-сервере автора стоит пересмотреть.
- Бюджет контекста: системный промпт не режется никогда, порядок обрезки фиксирован, ниже 16k токенов — компактный промпт; иначе llama.cpp молча обрезал правила и каталог инструментов.
- Tool-calling на 4–9B ненадёжен в цепочках; смягчения — «спасатель» текста, одноразовый толчок, строгие схемы с обязательными аргументами. Важно для MCP-хоста с T-lite 8B (§5.3).
- Семейство модели читается из метаданных GGUF (`general.architecture`), Qwen 3 получает no-think праймер по заголовку, не по имени файла.
- Лимиты фоновой обработки: ≤1000 писем — всё, больше — последние 365 дней на аккаунт.
- Смена провайдера/модели спрашивает про фоновые задачи — пакет в работе продолжал слать письма старому провайдеру. Для `ModelGateway` с четырьмя профилями (§5.4) прямая угроза.
- Эмбеддинг-модель внешнего провайдера сохраняется только после пробы на размерность; модели запоминаются на провайдер.
- Research-режим как map-reduce по письмам (1,5–2 с на письмо на 4B, ~30 мин на 1000) с оценкой и подтверждением пользователя; роли «пользователь/контрагент» назначает код, включая send-as алиасы из Sent.
- Их roadmap-пункт «обезличить тред и скопировать для внешней LLM» — сигнал, что спрос есть; наша проработка режима D глубже, брать нечего.

## 3. Практики

- Журнал решений в git: дата, решение, причина, отвергнутые варианты, измерения. Образец для наших ADR (этап −1 в CONCEPT §9).
- «Чистый планировщик + тонкий исполнитель»; trait-швы `EmailProvider`, `AIProvider`, `Clock`, `Keychain`, `Logger`; тестовая БД на продовых миграциях с тестом паритета схемы (таблицы, виртуальные таблицы, триггеры, индексы).
- Eval-харнесы как `[[example]]` Cargo, обязательны при любом изменении, влияющем на ответ ИИ, включая описания инструментов; приватные наборы вне репозитория (`private-evals/`). Совпадает с CONCEPT §5.5.
- Headless CLI поверх того же сервисного слоя с `--json`-конвертом — то же, что `aiowa-cli`.
- `.unwrap()`/`.expect()` запрещены на уровне крейта, исключения — точечный `#[allow]` с обоснованием.

Лицензия Apache-2.0 позволяет брать фрагменты кода с указанием авторства: санитайзер HTML, диспетчер `outbox`, `http_retry`, чтение метаданных GGUF, нарезка keychain под Windows.
