# ИИ-слой, этап 2: шлюз моделей, «Совет», поиск на обычном языке

Проект от 06.11.2026; решения автора по моделям, порядку, режиму и панели — в разделе 9. Основа — CONCEPT.md § 5 (поиск, «Совет»,
модели, шлюз и режимы приватности), § 7 (безопасность), `docs/pseudonymization-design.md` и уроки
EmailOps (`docs/emailops-review.md` § 2, «Этапы 2 и 4»). Здесь — что из концепции делаем сейчас,
как это ложится на код 0.2.8 и в каком порядке. Агент с инструментами (CONCEPT § 5.3) и
обезличивание (режим D) — следующие этапы, здесь только заделы под них.

## 0. Коротко

- **Порядок:** И1 шлюз моделей и вкладка «ИИ» в настройках → И2 «Совет» при ответе → И3 поиск на
  обычном языке (морфология, разбор запроса без модели, доводка моделью, «кратко по найденному»)
  → И4 смысловой поиск векторами, только после золотого набора запросов и только если он
  измеримо лучше. Каждый шаг — свой патч с живой проверкой и выпуском, как в обкатке.
- **«Совет» первым:** ему нужна только беседа из локальной базы и одна модель; ценность видна с
  первого письма. Поиску на обычном языке для честной оценки нужен золотой набор, а векторам —
  тела писем глубже текущих 90 дней.
- **Все обращения к моделям — из Rust**, через один шлюз (`ModelGateway`): окно в сеть не ходит
  (CSP), ключи не пересекают IPC, журнал обращений без содержимого — с первого дня.
- **ИИ по умолчанию выключен**; включается на вкладке «ИИ» после настройки подключения.
- **От автора нужно** (раздел 9): какие модели доступны сейчас (ключи, свои серверы), согласие на
  порядок, решение о глубине тел и 30–50 запросов для золотого набора.

## 1. Что уже есть в коде (0.2.8)

- **Поиск** (`aiowa-store`: `query.rs`, `Store::search`): операторы `от:`, `кому:`, `тема:`,
  `вложение:`, `папка:`, `после:`, `до:`, точные адреса; FTS5 `unicode61` без стемминга, слова
  ищутся как префиксы, ё = е (`fts_norm`); колонки — тема, отправитель, получатели, текст письма
  (`UniqueBody`, без цитат), текст вложений (PDF, DOCX, XLSX, TXT, вложенные `.eml`). Выдача — от
  новых к старым, `bm25` только разводит равные даты. Отдельного `index.db` из концепции нет, всё
  в `mail.db`.
- **Тела писем** качаются за окно «глубина тел» (по умолчанию 90 дней, настройка), остальные —
  по требованию при открытии (`message_fetch`). У старых писем в базе только тема, участники и
  начало текста (`preview`).
- **Композер** (`Composer.svelte`, `compose.rs`): ответ, ответ всем, пересылка, черновики с
  автосохранением и локальной копией, свёрнутая цитата сервера с «Развернуть», окна черновика
  (п. 32). Подпись из OWA.
- **Безопасность окна:** CSP без внешних адресов, письма в изолированной рамке, журнал без
  содержимого писем, адресов и имён вложений, пароль в диспетчере учётных данных Windows
  (`keyring`), HTTP через `reqwest` с `native-tls` (системные сертификаты).
- **Чего нет:** крейта `aiowa-ai`, морфологии в FTS, векторов, вырезания скрытого текста писем
  (`html_to_text` убирает теги, скрипты и стили, но не `display:none`, нулевой кегль и символы
  нулевой ширины), пометки конфиденциальности у писем (поле `Sensitivity` хранится только у
  событий календаря).

## 2. Принципы

1. **Тихий ИИ** (CONCEPT § 8): обычные кнопки без «искр», рядом всегда видно, какая модель
   работает («ИИ · облако · Claude Opus 5.5» или «ИИ · свой сервер · T-pro»).
2. **Один шлюз** (`ModelGateway`): сборка контекста → политика → (позже обезличивание) →
   провайдер → журнал. Функции не знают, куда уходит запрос.
3. **Письмо — недоверенный ввод.** Текст писем подаётся модели как данные в явной разметке,
   скрытый текст вырезается, у модели нет инструментов и права что-то делать — только вернуть
   текст. Черновик никогда не отправляется сам и попадает в письмо только по кнопке.
4. **Ответ модели — тоже недоверенный.** В окне он показывается как текст (никакого HTML от
   модели), ссылки на письма — только на письма из переданного контекста.
5. **Что можно посчитать кодом, считает код** (урок EmailOps): списки, счётчики, даты, роли
   «я / собеседник», кто в копии — не модель.
6. **Ссылки на письма — идентификаторами** (`[msg:12345]` по нашему `item_pk`), не номерами по
   порядку: модель путает нумерацию (урок EmailOps).
7. **JSON — только по схеме** (structured outputs у облака, `json_schema` у OpenAI-совместимых
   серверов, где поддержано), иначе — проверка схемы и повтор.
8. **Смена профиля или модели отменяет идущие запросы** (урок EmailOps: пакет продолжал ходить к
   старому провайдеру).
9. **Измеряем:** у «Совета» — сколько черновиков вставлено и насколько их правили перед отправкой,
   у поиска — золотой набор (CONCEPT § 5.5).

## 3. И1. Шлюз моделей и вкладка «ИИ»

### 3.1. Крейт `aiowa-ai`

Без Tauri, как `aiowa-sync`; тестируется на фейковом сервере (axum), как транспорт OWA.

- **Трейт провайдера:** `chat_stream(запрос) → поток событий` (текст по кусочкам, итог: причина
  остановки, токены), `chat_json(запрос, схема) → значение`, `list_models()`, позже `embed()`.
  Отмена — `CancellationToken`, длинные таймауты настраиваются (свои серверы бывают медленными).
- **Адаптер OpenAI-совместимый** — vLLM, Ollama, LM Studio, llama.cpp server, сам OpenAI:
  `POST {base}/v1/chat/completions` со `stream: true` (SSE, строки `data: {…}`, конец —
  `data: [DONE]`), `GET {base}/v1/models`, `POST {base}/v1/embeddings`. JSON — через
  `response_format: {type: "json_schema", …}`, если сервер его понимает (проверяется при
  «Проверить подключение»), иначе схема в промпте и проверка. Семейство Qwen3 — с выключенным
  режимом размышлений для разбора запроса (CONCEPT § 5.4).
- **Адаптер Anthropic** — Messages API напрямую по HTTP (официального SDK для Rust нет):
  `POST https://api.anthropic.com/v1/messages`, заголовки `x-api-key`,
  `anthropic-version: 2026-10-21`. Поток — SSE-события `message_start`, `content_block_start`,
  `content_block_delta` (`text_delta`), `content_block_stop`, `message_delta` (причина остановки,
  токены), `message_stop`. JSON — `output_config.format` со схемой; глубина рассуждения —
  `output_config.effort` (`low` для разбора запроса, `medium`/`high` для «Совета»). Параметров
  выборки (`temperature`) у текущей версии API нет — запрос с ними отклоняется, поэтому «ровность»
  совета задаётся промптом и `effort`, а не температурой, как предлагала концепция. Причину
  остановки `refusal` показываем текстом «Модель отказалась отвечать», а не пустым черновиком.
  Кэш промпта: `cache_control` на неизменной голове (системный промпт и правила) — у текущих
  моделей кэшируется голова от 512 токенов; голова не должна меняться от запроса к запросу (никаких
  дат и счётчиков в ней). Список моделей и их окна контекста — `GET /v1/models`
  (`max_input_tokens`, `max_tokens`).
- **Модели Claude на 06.11.2026** (цены за 1 млн токенов, вход/выход): Claude Opus 5.5
  (`claude-opus-5-5`, $4/$20) — лучший кандидат для «Совета»; Claude Sonnet 5.5
  (`claude-sonnet-5-5`, $2/$10) — дешевле; Claude Haiku 5.5 (`claude-haiku-5-5`, $0,10/$0,50) — для
  быстрого разбора запросов. У всех окно 1 млн токенов. Оценка «Совета» на Opus 5.5: ~10 тыс.
  токенов контекста и ~1 тыс. ответа — около 6 центов за совет.

### 3.2. Профили и назначения

- **Профиль подключения:** имя, тип (OpenAI-совместимый или Anthropic), адрес, ключ, модель,
  таймаут, класс адресата (свой компьютер / свой сервер в сети / облако — для политики), TLS:
  системные сертификаты, для своих серверов с самоподписанным сертификатом — «доверять этому
  сертификату» по отпечатку SHA-256 (не выключать проверку целиком). Системный прокси — как у OWA.
- **Ключи** — в диспетчере учётных данных Windows (`keyring`, запись на профиль); окно видит
  только «ключ задан». Настройки профиля без ключа — в таблице настроек базы, как остальные
  (`desktop.*`).
- **Назначения:** «Совет» (сильная модель), «Разбор запроса» (быстрая), позже «Эмбеддинги».
  Одно назначение — один профиль; без профиля функция выключена и её кнопки не видно.

### 3.3. Политика и журнал

- **Режимы** (CONCEPT § 5.6): в коде перечисление A/B/C/D; в MVP работают A (любые модели) и B
  (только свой компьютер и свои серверы) — B стоит дёшево и нужен для проверки самой политики.
  C и D — следующие этапы. Проверка режима — в шлюзе перед отправкой, не в окне.
- **Журнал обращений** — таблица `ai_calls` в `mail.db`: время, функция («совет», «разбор»,
  «кратко»), профиль, адресат (хост), модель, токены, длительность, исход, SHA-256 отправленного.
  Ни текста, ни адресов, ни тем. На вкладке «ИИ» — последние обращения и итог за месяц
  (токены, примерная стоимость для облака).
- **«Что уйдёт в модель»** — в панели «Совета» кнопка показывает собранный контекст до отправки
  (локально, ничего не отправляя).
- **Письма, которые модели не отдаются:** зашифрованные (S/MIME, IRM) — у нас их тела и так нет;
  пометку конфиденциальности (`Sensitivity` = `Private`/`Confidential`) нужно начать хранить и у
  писем, и такие письма в облачный профиль отдавать только после подтверждения (проверить, что
  сервер отдаёт поле в `SyncFolderItems`).

### 3.4. Вкладка «ИИ» в настройках

Выключатель «ИИ-функции» (по умолчанию выключен); профили: добавить, изменить, «Проверить» (список
моделей, короткий запрос, поддержка JSON-схемы, время ответа), удалить; назначения; режим (A/B);
журнал. Пока ИИ выключен, функции к моделям не обращаются; «Проверить» — явное действие автора и
работает всегда (по режиму приватности). Как сделано — раздел 10.

## 4. И2. «Совет» при ответе

### 4.1. Где и как выглядит

- В композере ответа, ответа всем и пересылки — тихая кнопка «Совет» в строке кнопок (рядом с
  «Подпись…»); в главном окне, в окне беседы и в окне черновика одинаково (это один `Composer`).
- По кнопке над редактором открывается панель: поле «Что ответить» (направление: «согласиться, но
  перенести на пятницу», «вежливо отказать»), чипы тона — «короче», «подробнее», «мягче»,
  «официальнее»; «Вы» или «ты» и обращение по имени-отчеству код определяет сам по прошлой переписке.
  Кнопка «Посоветовать». Строка модели: «ИИ · облако · Claude Opus 5.5».
- Ответ идёт потоком в два блока: **«Суть»** — 2–4 пункта, что происходит и чего от тебя ждут,
  каждый с чипами-ссылками на письма беседы (по клику — к письму); **«Черновик»** — текст ответа.
  Кнопки: «Вставить в письмо» (в начало, над подписью и цитатой), «Заменить мой текст», «Ещё
  вариант», чипы тона для доработки. Проверка фактов (4.3) — строкой под черновиком.
- Для нового письма без беседы «Совет» в v1 не показывается (нечего советовать по переписке);
  «помоги написать» — позже, если понадобится.

### 4.2. Контекст (собирает Rust, детерминированно)

- **Беседа** из локальной базы — все письма беседы во всех папках (как в окне беседы), по времени.
  Для каждого: дата, от кого, кому, копия (роли: я / собеседник / в копии), тема, текст `UniqueBody`
  (без истории цитат — она уже в предыдущих письмах), имена вложений; текст вложений — для
  последних писем и в пределах бюджета. Тела, которых нет локально, сначала догружаются
  (`message_fetch`), с прогрессом в панели.
- **Свой стиль:** 3–5 моих последних писем этому адресату из «Отправленных» (только их начало),
  как пример тона и обращения. Подпись не пишется — она уже в письме.
- **Обо мне:** имя из профиля учётной записи, пол — по отчеству или по прошлым письмам (для
  «согласен» / «согласна»), сегодняшняя дата (в конце, не в кэшируемой голове).
- **Бюджет:** для своих 7–9B моделей ~8 тыс. токенов, для облака — до ~30 тыс. Обрезаются сначала
  тексты вложений, затем старые письма (от самых старых: остаётся шапка и первые строки);
  последние 5 писем — всегда целиком. Саммари старой части беседы моделью — позже, если не хватит.
- **Очистка:** новая функция извлечения текста для модели — та же выжимка из HTML плюс вырезание
  скрытого (`display:none`, `visibility:hidden`, нулевой кегль, текст цвета фона, символы нулевой
  ширины), тех же шаблонов, что используют для подброса инструкций в письма. Её же потом
  использует обезличивание (`pseudonymization-design.md` § 3.1).
- **Разметка:** каждое письмо — в теге с `id`; системный промпт явно говорит, что содержимое
  писем — данные, инструкции из них не выполняются.

### 4.3. Защита от выдумок

- Числа, даты, суммы, проценты, адреса почты, телефоны и имена из черновика ищутся в контексте;
  не найденные перечисляются под черновиком: «Проверь: 15 000 ₽, 12 ноября — в переписке этого
  нет». В редакторе ничего не подсвечивается — после вставки текст уже твой.
- Где модели не хватает данных, она ставит «[уточнить: …]», а не выдумывает (правило в промпте,
  проверяется на наборе сценариев).
- Ссылки `[msg:…]` на письма вне контекста отбрасываются.

### 4.4. Измерение

Локально, без содержимого: вставлен ли черновик, заменил ли текст, отброшен ли, и при отправке —
какая доля вставленного текста дошла без правки. Критерий концепции: из 20 реальных ответов ≥ 10
ушли с правкой меньше 30 %. Плюс 30–50 сценариев из своей почты для сравнения моделей (вне
репозитория).

## 5. И3–И4. Поиск на обычном языке

### 5.1. И3а. Русская морфология в FTS

Теневая колонка со стеммингом Snowball (`rust-stemmers`) для темы, текста и вложений, сырая
колонка остаётся для фраз в кавычках и точных совпадений. Улучшает и обычный поиск («договора»
находит «договор», «договору»). Миграция схемы с переиндексацией в фоне (на 100 тыс. писем — минуты),
поиск во время переиндексации работает по старой колонке.

### 5.2. И3б. Разбор запроса без модели

- Строка поиска та же. Запрос без операторов из трёх и более слов, похожий на фразу («что писал
  Вася про запчасти на Колыму в прошлом месяце»), разбирается в фильтры, которые показываются
  чипами над результатами и правятся: «от: Василий Петров ▾» (2–3 кандидата), «период: октябрь
  2026», «с вложениями», остальное — слова поиска. Там же видно, во что превратился запрос в
  операторах — им можно пользоваться и дальше.
- **Люди:** «от / писал / прислал» — отправитель, «мне / я писал / переписка с» — направление;
  имена — по корреспондентам из базы (частота, давность) и справочнику, с уменьшительными
  (словарь ~400 имён: Вася → Василий, Саша → Александр/Александра), отчествами, падежами и ё/е.
- **Даты по-русски:** «вчера», «на прошлой неделе», «в прошлом месяце», «в октябре», «летом 2024»,
  «перед Новым годом» — код, не модель.
- **Прочее:** «с файлом / в таблице / в договоре (pdf)» — вложения, «во входящих / в архиве» —
  папка, числа и артикулы — точные слова.
- Если разбор дал меньше 3 результатов, фильтр по человеку ослабляется с пометкой «показаны и
  письма с упоминанием Васи».

### 5.3. И3в. Доводка моделью и «Кратко по найденному»

- Если разбор оставил непонятный хвост, быстрая модель (назначение «Разбор запроса») асинхронно
  возвращает фильтры по JSON-схеме; результат применяется, только если пользователь за это время
  не изменил запрос, и показывается теми же чипами. Разборы кэшируются. Быстрый путь от модели не
  зависит.
- **«Кратко по найденному»:** кнопка над результатами — модель читает до 20 верхних писем
  (контекст собирается так же, как для «Совета») и отвечает на вопрос из строки поиска с
  чипами-ссылками на письма. Счётчики («сколько писем от…») — кодом, не моделью.

### 5.4. И4. Смысловой поиск (векторы) — после измерений

- Только после золотого набора: 50–150 запросов из своей почты с отметкой правильных бесед,
  файл вне репозитория (`%LOCALAPPDATA%\AIOWA\eval\`), прогон `aiowa eval` (Recall@10, nDCG@10,
  время). Векторы включаются, только если дают ≥ 10 пунктов Recall@10 к FTS с морфологией
  (CONCEPT § 5.5).
- Эмбеддинги — профиль «Эмбеддинги»: свой сервер с GPU (`/v1/embeddings`; кандидаты — FRIDA,
  Giga-Embeddings, USER-bge-m3, выбор по золотому набору) или ONNX на процессоре ноутбука (дольше,
  тяжёлая зависимость — отдельный крейт). Хранение — `sqlite-vec`, слияние с FTS — RRF.
- **Ограничение данных:** векторы имеют смысл по телам писем, а тела у нас за 90 дней. Для поиска
  по смыслу за годы нужна фоновая догрузка тел за выбранный период (сколько места и времени — замер
  до решения).

## 6. Данные

- `mail.db`: таблица `ai_calls` (журнал), новые настройки `ai.*`; позже — колонка стеммированного
  текста в FTS, `sensitivity` у писем, таблица разборов запросов, векторы (тогда — отдельный
  `index.db`, как в концепции: его можно пересобрать, а `mail.db` растёт медленнее).
- Ключи — только в диспетчере учётных данных. Золотой набор и сценарии «Совета» — вне репозитория.
- Журнал приложения (`logs`) — по прежней политике: без текстов, адресов, тем и ключей; ответы и
  ошибки провайдеров — коды и счётчики.

## 7. Безопасность

Сверх раздела 3.3: ответ модели — текст без HTML; у модели нет инструментов (их появление — этап
агента с отдельными границами, CONCEPT § 5.3); облако в MVP разрешено политикой автора (режим A),
к обкатке на ящиках сотрудников режим ужесточается решением ИБ — переключение в одном месте.
Опросник ИБ (`docs/questionnaire-admins-security.md`) дополнить списком адресатов моделей и
форматом журнала обращений.

## 9. Решения автора

**Принято 06.11.2026:**

- **Модели:** есть ключ Anthropic, ключ OpenAI и свой сервер с моделями. В И1 — оба адаптера
  (Anthropic и OpenAI-совместимый: им же идут OpenAI и свой сервер). Для живой проверки своего
  сервера нужны адрес, программа (vLLM / Ollama / LM Studio) и названия моделей; ключи автор
  вводит сам на вкладке «ИИ», в переписку они не попадают.
- **Порядок:** после И1 — оба направления: «Совет» (И2) и поиск (И3а морфология, И3б разбор
  запроса). Они в разных частях кода (композер и `aiowa-store` со строкой поиска), их можно вести
  параллельно, выпускать — по готовности.
- **Режим A** без подтверждения каждого запроса: журнал обращений всегда, «Что уйдёт в модель» —
  по кнопке.
- **Панель «Совета»** — над редактором, одинаково во всех окнах.

**Открыто:** глубина тел для смыслового поиска (п. 4, к И4) и золотой набор (п. 5, к оценке И3).

Исходные вопросы:

1. **Модели сейчас.** Что есть: ключ Anthropic (или OpenAI), свой сервер с моделями (адрес,
   vLLM / Ollama / LM Studio, какие модели, сколько памяти у GPU)? От этого — с какого адаптера
   начинать И1 и чем проверять. Предложение: «Совет» — Claude Opus 5.5, разбор запроса — Claude
   Haiku 5.5 или своя быстрая модель.
2. **Порядок.** «Совет» первым (рекомендую) или поиск первым.
3. **Режим A для MVP** (только ты и твой ящик): облако без подтверждения каждого запроса, журнал
   всегда, «Что уйдёт в модель» — по кнопке. Подтверждаешь?
4. **Глубина тел для смыслового поиска** (И4, не срочно): догружать тела за 2–3 года — сначала
   замерю, сколько это места и времени.
5. **Золотой набор:** готов набросать 30–50 запросов «как бы спросил» и отметить правильные
   письма? Нужен к И3; храним вне репозитория.
6. **Панель «Совета»:** над редактором в композере (предлагаю, одинаково во всех окнах) или сбоку
   в окне черновика.

## 10. Ход работы

### И1 — сделан 06.11.2026 (в `main`, войдёт в следующий выпуск)

- **Крейт `aiowa-ai`** без новых зависимостей (кэш крейтов офлайн): `Profile` (протокол, адрес,
  модель, таймаут, «свой сервер», дополнительные поля), `Place` по адресу (облако — известные
  домены и всё внешнее; свой сервер — частные адреса, имена без точки и внутренних зон, отметка
  автора; этот компьютер — `localhost`), `PrivacyMode` A/B, разбор SSE с кусками посреди символа,
  адаптеры Anthropic (`anthropic-version: 2026-10-21`, `output_config.effort`, блоки размышлений
  пропускаются, `refusal` — причина остановки) и OpenAI-совместимый (`max_tokens`, у облака OpenAI —
  `max_completion_tokens` и `stream_options`; `reasoning_content` в текст не идёт), ответ целиком
  JSON вместо потока, таймаут профиля — до первого байта и между кусками, отмена посреди потока,
  `CallRecord` с SHA-256 тела. Тесты: 18 модульных и 4 на фейковых серверах (поток, ключи в
  заголовках, отказы по кодам, политика, таймаут, отмена, журнал, ответ без потока).
- **Дополнительные поля запроса** у OpenAI-совместимых — JSON-объект профиля, добавляется к
  каждому запросу, не меняя `model`, `messages`, `stream` и длину ответа. Нужны своему шлюзу
  Горыныч: `priority`, `notes: false` (иначе пометка о подмене головы попала бы в текст),
  `reasoning_effort` (у `smart` не `xhigh` — это совет на 15–30 минут).
- **Журнал** — таблица `ai_calls`, схема v12, полгода; итоги за 30 дней по подключению и модели.
- **Приложение** (`ai.rs`): настройки `ai.*` в `sync_state`, профили одним JSON, ключи — в
  диспетчере учётных данных (`ai:<профиль>`), окну возвращается только «ключ задан»; смена адреса
  или протокола без нового ключа удаляет старый; новая проверка профиля отменяет прежнюю.
- **Вкладка «ИИ»** (`AiSettings.svelte`): выключатель, режим, подключения с заготовками
  (Anthropic, OpenAI, DeepSeek, Gemini, свой сервер), «Проверить» — список моделей (окно контекста:
  `max_input_tokens`, `max_model_len`, `context_length`, `ctx`), ответ модели, время до первого
  куска и токены, выбор модели нажатием; назначения «Совет» и «Разбор запросов»; журнал.
- **Не сделано из § 3:** доверие самоподписанному сертификату своего сервера (свои серверы пока
  по http в локальной сети); `Sensitivity` у писем (к И2); проверка поддержки JSON-схемы (к И3).

Проверено вживую 06.11.2026 в окне разработки: шлюз Горыныч `http://192.168.0.79:4000/src/aiowa/v1`
без ключа, «свой сервер» — `fast` (Qwen 27B) отвечает за 0,4–0,5 с, `smart` с
`reasoning_effort: high` — за 6–22 с (голову шлюз выбирает сам); Gemini по OpenAI-совместимому
адресу `https://generativelanguage.googleapis.com/v1beta/openai` — 61 модель, `models/gemini-3.6-flash`
и 3.5 отвечают за 3–4 с, 3.7 и 3.8 на ключе автора отвечают ошибкой сервера. Токены Gemini в журнал
не попадают: в потоке он их не присылает без `stream_options` (включить после проверки на ключе
автора). Anthropic, OpenAI и DeepSeek проверены на фейковых серверах; вживую — когда автор добавит
ключи. Назначения автора: «Совет» и разбор запросов — Горыныч `smart`.

### И2 — сделан 06.11.2026 (в `main`, войдёт в следующий выпуск)

- **Где.** Кнопка «Совет» в строке композера ответа, ответа всем и пересылки (во всех окнах — это
  один композер), если ИИ включён и для «Совета» назначена модель с выбранной моделью. Вид письма и
  исходное — из заготовки: после «Развернуть» совет по беседе остаётся.
- **Панель** (`AdvicePanel.svelte`) над редактором: «Что ответить», чипы тона (короче, подробнее,
  мягче, официальнее), «Посоветовать» (Ctrl+Enter в поле — не «Отправить»), «Остановить», строка
  модели «ИИ · место · подключение (модель)», «Что уйдёт в модель» — собранный промпт без отправки.
  Ответ кусками: «Суть» — пункты с чипами писем (по нажатию — к карточке письма), «Черновик».
  После ответа — «Вставить в письмо» (в начало, одна пустая строка до подписи), «Заменить мой
  текст» (черновик и подпись заново; скрыта, если цитата развёрнута в редактор), «Ещё вариант»,
  время и токены; «Проверь: …» — числа и адреса черновика, которых нет в переписке и словах автора;
  пометки «обрезано по длине» и «модель отказалась».
- **Контекст** (`advice.rs` приложения): письма беседы без черновиков, до 40 свежих, от старых к
  новым; тела последних пяти и исходного догружаются с сервера (`ensure_body`, первая ошибка связи
  останавливает догрузку); у писем — дата, отправитель и получатели с ролью «автор» или
  «собеседник», тема, видимый текст (`mailtext::strip_hidden_html` вырезает `display:none`,
  `visibility:hidden`, нулевой кегль и прозрачность, `hidden`; `strip_invisible` — символы нулевой
  ширины и управления направлением), имена вложений; три моих письма главному адресату из
  «Отправленных» — образец стиля (`Store::sent_to`); моё имя по «Отправленным», сегодняшняя дата,
  уже набранный текст. Промпт и бюджет — `aiowa_ai::advice` (облако — 90 тыс. символов данных,
  свои модели — 40 тыс.; урезаются старые письма, затем примеры стиля, затем свежие, исходное —
  последним). Текст письма не может закрыть разметку `<письмо>`. Неизменная голова промпта — без
  дат. В журнал — как «совет».
- **Не сделано из § 4:** учёт правки вставленного черновика до отправки (§ 4.4); саммари старой
  части длинной беседы моделью; `Sensitivity` у писем; «помоги написать» для нового письма.
- **Замечено:** индекс поиска скрытый текст писем не вырезает — сниппет поиска показал текст
  скрытого блока тестового письма. Для «Совета» это не важно; для поиска — поправить при И3а
  (переиндексация всё равно будет).
