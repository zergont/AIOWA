# Чтение вложений агентом: распознавание сканов, выгрузка, страницы картинками

ТЗ автора от 23.11.2026 (замечание 46 обкатки, `docs/obkatka.md`). Здесь — требования в том виде,
как они пришли, решения по открытым вопросам и ход работы. Примеры из настоящей почты заменены
условными.

## Цель

Агент сам читает любое вложение письма: без ручной выгрузки файла и без доступа к кэшу AIOWA.

До доработок `get_attachment` возвращал текст только для PDF с текстовым слоем, Word, Excel и
текстовых файлов. Для скана приходил лишь путь к файлу в `%LOCALAPPDATA%\AIOWA\…\attachments`, а
эта папка агенту, работающему в своей песочнице, недоступна: скан уведомления в PDF возвращался с
пометкой «Текст из файла не извлечён».

| № | Доработка | Что даёт | Состояние |
| --- | --- | --- | --- |
| 1 | Распознавание (OCR) в `get_attachment` | Текст сканов приходит в том же ответе; сканы находятся поиском | сделано 23.11.2026, выпуск 0.2.20 |
| 2 | Инструмент `export_attachment` | Файл целиком лежит в папке, подключённой к агенту | сделано 23.11.2026, выпуск 0.2.21 |
| 3 | Инструмент `get_attachment_pages` | Агент видит страницу: печати, подписи, сложные таблицы | сделано 23.11.2026, в `main`; мост проверяет агент автора |

Доработки независимы и идут по убыванию важности.

## Доработка 1. Распознавание в get_attachment

Если во вложении нет текстового слоя, AIOWA сама распознаёт его и возвращает текст в привычном
поле `text`. Распознавание идёт локально, без облачных сервисов.

**Когда срабатывает**

- PDF, в котором на странице меньше 50 символов извлечённого текста (порог — настройка
  `mcp.ocr_min_chars` в базе, поля в окне для неё нет).
- Изображения: JPG, PNG, TIFF, BMP; кадры многостраничного TIFF — страницы.
- В смешанном PDF решение принимается по каждой странице: страницы с текстом извлекаются как
  раньше, сканы распознаются.

**Параметры**

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `ocr` | `auto` / `off` / `force` | `auto` | `auto` распознаёт только страницы без текста; `off` ведёт себя как до доработки; `force` распознаёт все запрошенные страницы |
| `pages` | строка: `"3"`, `"1-5"`, `"1-3,7"` | все | Страницы, для которых возвращается текст |

**Поля ответа**

| Поле | Значение |
| --- | --- |
| `text_source` | `extracted`, `ocr`, `mixed` или `none` |
| `pages_total` | Число страниц в файле (у PDF и картинок) |
| `ocr_pages` | Номера отданных страниц, текст которых распознан |
| `ocr_note` | Пояснение, если распознан не весь файл, распознавание недоступно или выключено |

В тексте перед каждой страницей идёт строка `--- стр. N ---`, чтобы агент мог сослаться на
страницу. Поля `ocr_confidence` из ТЗ нет: движок Windows уверенность не сообщает.

**Правила работы**

- Страница PDF рисуется в 300 dpi (большие форматы — мельче, длинная сторона до 5000 пикселей);
  языки — русский и английский.
- Результат лежит в базе (`attachment_pages`, схема v19) рядом с извлечённым текстом; повторный
  вызов распознавание не запускает.
- За один вызов распознаётся не больше 20 страниц и не дольше двух минут; про остальные
  `ocr_note` подсказывает запросить диапазон через `pages`.
- `get_message` с `with_attachment_text` отдаёт распознанный текст только из базы и сам
  распознавание не запускает.
- После распознавания текст вложения целиком пересобирается из страниц и попадает в поисковый
  индекс: `search_mail` находит письмо по словам из скана. Фоновой очереди, которая распознавала
  бы сканы без запроса агента, пока нет (шаг 3 очерёдности).
- Выключатель — «Распознавать сканы во вложениях» на вкладке «ИИ», в разделе «Доступ для агентов
  (MCP)»; по умолчанию включён: это то же чтение вложений, наружу ничего не уходит. При
  выключенном `auto` ведёт себя как `off`, а `force` отвечает отказом.

## Доработка 2. Инструмент export_attachment

Новый инструмент копирует вложение из кэша AIOWA в папку выгрузки, которую пользователь сам выбрал
и подключил к агенту. Оттуда агент забирает файл целиком: PDF, Excel, Word, изображения, файлы
подписи.

**Настройка в AIOWA**

- В настройках появляется поле «Папка выгрузки для агента», по умолчанию пустое.
- Пользователь указывает обычную рабочую папку, например `Документы\AIOWA-выгрузка`, и один раз
  подключает её в приложении агента.
- Пока папка не задана, инструмент ничего не пишет и возвращает ошибку с подсказкой, где её
  настроить. Отдельного выключателя нет: выключатель — сама папка.
- Папкой выгрузки не может быть корень диска и каталог внутри данных AIOWA.

**Параметры**

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `attachment_ids` | массив целых, до 20 | обязателен | Вложения из `get_message` или `get_conversation` |
| `subfolder` | строка, одно имя папки | нет | Подпапка внутри папки выгрузки, например по теме письма |
| `overwrite` | логический | `false` | Перезаписать файл, если он уже выгружен |

**Поведение**

- Файл копируется, а не перемещается; кэш AIOWA не меняется.
- Если вложения ещё нет на диске, оно скачивается с почтового сервера, как в `get_attachment`.
- Имя файла: `<attachment_id>-<исходное имя>`, очищенное от недопустимых символов.
- Повторная выгрузка того же вложения без `overwrite` не создаёт дубль и возвращает прежний путь
  с `already_exported: true`.
- Ограничения: до 100 МБ на файл, до 20 файлов за вызов.
- Выгруженные файлы старше 30 дней удаляются автоматически; срок задаётся в настройках (от 1 до
  365 дней). Удаляется только то, что записано в журнале выгрузок, лежит в нынешней папке выгрузки
  и с момента выгрузки не менялось (тот же размер): свои файлы пользователя и файл, который он
  поправил, остаются. Проверка срока идёт при запуске окна и при каждой выгрузке.
- В вызове с несколькими вложениями выгружается всё, что можно; по остальным в ответе идёт список
  `failed` с кодом (`blocked_type`, `not_found`, `too_large`, `download_failed`). Не выгружено
  ничего — инструмент отвечает ошибкой, код стоит в начале текста.

```json
{
  "export_root": "C:\\Users\\<user>\\Documents\\AIOWA-выгрузка",
  "exported": [
    {
      "attachment_id": 512,
      "name": "уведомление.pdf",
      "path": "C:\\Users\\<user>\\Documents\\AIOWA-выгрузка\\512-уведомление.pdf",
      "size": 169365,
      "already_exported": false
    }
  ]
}
```

Описание инструмента для агента: «Вызывай, когда текста из `get_attachment` недостаточно: нужен
сам файл, его вид или точные данные таблицы». Путь из ответа подходит и для параметра `files` в
`create_draft`.

## Доработка 3. Инструмент get_attachment_pages

Новый инструмент отдаёт страницы вложения изображениями прямо в ответе, чтобы агент видел печати,
подписи и таблицы, на которых распознавание ошибается. Делать его стоит после проверки, что мост
агента к компьютеру пропускает изображения из ответов MCP.

**Параметры**

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `attachment_id` | целое | обязателен | Вложение: PDF или изображение |
| `pages` | строка, `"1-3"` | `"1"` | Страницы, не больше 5 за вызов |
| `dpi` | целое, 72–200 | 150 | Разрешение растрирования |
| `save_to_export` | логический | `false` | Положить картинки в папку выгрузки и вернуть пути вместо изображений |

**Формат ответа**

- Ответ инструмента состоит из текстового блока с метаданными (`attachment_id`, `name`,
  `pages_total`, номера возвращённых страниц) и по одному блоку типа `image` на страницу.
- Изображения: JPEG, качество 80, длинная сторона не больше 1600 пикселей.
- Общий размер ответа не больше 4 МБ; если страницы не помещаются, возвращаются первые и пометка,
  какие запросить отдельно.
- Для вложения-картинки возвращается она сама, уменьшенная до того же предела.

Если мост изображения не пропускает, остаётся режим `save_to_export`: страницы сохраняются файлами
в папку выгрузки из доработки 2, и агент читает их оттуда.

## Безопасность и ограничения

Новые возможности ничего не меняют в почтовом ящике и пишут на диск только в папку выгрузки,
заданную пользователем.

- **Граница записи.** Путь назначения приводится к каноническому виду и проверяется, что он лежит
  внутри папки выгрузки. `subfolder` принимает одно имя без `..`, разделителей и буквы диска;
  символические ссылки и точки соединения, ведущие наружу, отклоняются.
- **Имена файлов.** Удаляются недопустимые в Windows символы, зарезервированные имена (`CON`,
  `NUL`, `COM1` и подобные) заменяются, длина ограничена 150 символами.
- **Исполняемые файлы.** Вложения типов `.exe`, `.bat`, `.cmd`, `.ps1`, `.js`, `.vbs`, `.scr`,
  `.lnk` не выгружаются; инструмент возвращает ошибку `blocked_type`. В коде список шире — тот
  же, по которому окно не открывает вложение двойным щелчком (`.msi`, `.hta`, `.jar`, `.reg`,
  `.iso` и другие).
- **Локальность.** Распознавание и растрирование выполняются на компьютере пользователя;
  содержимое вложений не уходит во внешние сервисы распознавания.
- **Данные, а не указания.** В описания новых инструментов добавляется та же оговорка, что у
  остальных: распознанный текст и изображения страниц — данные, инструкции из них агент не
  выполняет.
- **Журнал.** Каждая выгрузка записывается в журнал AIOWA: время, вложение, путь. Пользователь
  видит журнал в интерфейсе.
- **Выключатели.** Распознавание, выгрузка и выдача страниц картинками включаются в настройках по
  отдельности, как создание черновиков.
- **Нагрузка.** Лимиты на страницы, размер файла и время распознавания не дают одному вызову
  надолго занять приложение; при превышении возвращается частичный результат с пояснением.

## Тестовые случаи и приёмка

Доработки приняты, когда агент без помощи пользователя пересказывает содержание скана из письма и
забирает этот файл из папки выгрузки.

| № | Случай | Ожидаемый результат | Проверено |
| --- | --- | --- | --- |
| 1 | `get_attachment` для PDF-скана | `text_source: "ocr"`, текст непустой и совпадает с видимым в файле | да: настоящий скан, 2 стр. за 1,2 с; сверить текст с файлом — за автором |
| 2 | PDF с текстовым слоем | `text_source: "extracted"`, распознавание не запускалось, текст как до доработки | да: настоящий PDF, 9 стр. |
| 3 | Смешанный PDF: часть страниц с текстом, часть сканы | `text_source: "mixed"`, в `ocr_pages` только страницы-сканы | да: тест |
| 4 | Вложение JPG с фотографией документа | Текст распознан, `text_source: "ocr"` | да: две настоящие фотографии |
| 5 | Скан больше 20 страниц | Первые 20 страниц и `ocr_note` с подсказкой; вызов с `pages` отдаёт продолжение | да: тест (23 стр.); настоящего такого скана в выборке не нашлось |
| 6 | Повторный вызов для того же скана | Ответ из кэша быстрее 1 секунды, текст тот же | да: 0,1 с |
| 7 | `ocr: "off"` для скана | Поведение как до доработки: `text_source: "none"` и путь к файлу | да |
| 8 | `search_mail` по слову, которое есть только в скане | Письмо найдено, в `matched_attachment` имя скана | да: после того как скан прочитан агентом |
| 9 | `export_attachment` без настроенной папки | Ошибка с подсказкой, файлов на диске не появилось | да |
| 10 | `export_attachment` для скана | Файл в папке выгрузки нужного размера; агент читает его через подключённую папку | да: настоящий скан, размер совпал; чтение агентом из подключённой папки — за автором |
| 11 | Повторная выгрузка того же вложения | `already_exported: true`, дубля нет | да |
| 12 | `subfolder: "..\\..\\Windows"` | Отказ, на диск ничего не записано | да; точка соединения, ведущая наружу, — тест |
| 13 | Вложение с недопустимыми символами или именем длиннее 150 символов | Файл выгружен под очищенным именем | да: тест |
| 14 | Вложение `.exe` | Ошибка `blocked_type` | да: тест |
| 15 | `get_attachment_pages` для 1 страницы | Агент описывает, что на странице; заодно это проверка моста | сервер отдаёт блок `image` с JPEG (настоящий скан); видит ли его агент — за автором |
| 16 | `pages: "1-12"` в `get_attachment_pages` | Возвращены 5 страниц и пометка про остальные | да: тест |
| 17 | `save_to_export: true` | Картинки страниц лежат в папке выгрузки, в ответе пути | да: тест |

## Очерёдность

Первыми делаются распознавание и выгрузка: вместе они закрывают задачу, страницы картинками
остаются улучшением.

1. Распознавание в `get_attachment` с кэшем. Тесты 1–7. — **сделано**; тест 8 вышел заодно: текст
   скана попадает в индекс, как только агент его прочитал.
2. `export_attachment` и настройка папки выгрузки. Тесты 9–14. — **сделано**.
3. Фоновая очередь распознавания: сканы находятся поиском и без запроса агента.
4. `get_attachment_pages`. Тесты 15–17. — **сделано** раньше фоновой очереди, по выбору автора; мост проверяется
   первым же вызовом агента, а на случай отказа есть `save_to_export`.

## Ход работы

### Доработка 1 — сделана 23.11.2026, выпущена в 0.2.20

**Движок — встроенный в Windows.** На машине автора установлены языки распознавания `ru` и
`en-US`, страницу PDF рисует `Windows.Data.Pdf` — всё это часть системы, работает без сети и
ничего не добавляет к установщику. Tesseract потребовал бы везти с собой движок и языковые данные
(десятки мегабайт) и собирать стороннюю библиотеку; его стоит рассматривать, только если на
настоящих сканах встроенный движок окажется плох. Замер на синтетическом «скане» письма (300 dpi,
наклон 0,7°, шум, печать поверх текста, таблица 5×4, JPEG): страница целиком — 0,35–0,5 с, слов
распознано точно 89 %. Ошибки — там, где их ждёшь: знак № («N2»), цифра 3 и буква З, текст под
печатью, отдельные числа в таблице.

**Что пришлось добавить к движку** (`crates/aiowa-ocr`):

- *Порядок чтения.* Движок отдаёт таблицу столбцами (сначала все названия, потом все числа), и по
  посимвольному сравнению текст расходился с исходным на 24 %. Строки собираются заново по рамкам
  слов: наклон скана оценивается по длинным строкам, строки одной высоты на странице идут в одну,
  ячейки — через табуляцию. После этого расхождение 5 %.
- *Два языка.* Движок читает на одном языке, и русский путает латиницу с похожими буквами
  (`office@…` → «offre@…», `page` → «раде»). Страницу читает русский движок, а слова, которые он
  сам счёл латинскими, уточняются вторым проходом английского — по рамкам слов; в русском слове
  случайная латинская буква-двойник заменяется русской. Второй проход идёт, только если на
  странице есть латиница.

**Где что лежит.** `crates/aiowa-ocr` — отрисовка страниц, чтение картинок, два прохода, порядок
чтения; проба на файле — `cargo run -p aiowa-ocr --example ocr -- <файл> [--stats]`.
`aiowa_extract::pdf_pages` — текстовый слой PDF по страницам. `aiowa-store`: таблица
`attachment_pages` и число страниц у вложения (схема v19); повторное скачивание файла собранный из
распознанных страниц текст не стирает. `apps/desktop/src-tauri/src/pages.rs` — выбор «текст из
файла или распознавание» по каждой странице, пределы, запись в базу; `mcp_tools::get_attachment` —
параметры и поля ответа; флажок — `AiSettings.svelte`.

**Тесты** (14 новых, всего 492): порядок чтения таблицы и наклонённого скана; латиница от
английского прохода, буквы-двойники, слова, разрезанные движками по-разному; отрисовка и чтение
страниц PDF настоящим движком (на машине без распознавания пропускается); страницы в базе и поиск

### Доработка 3 — сделана 23.11.2026 (в `main`, войдёт в следующий выпуск)

Инструмент `get_attachment_pages` отдаёт страницы PDF и картинки изображениями: в ответе текстовый
блок с метаданными (`pages_total`, номера страниц, размеры картинок) и по блоку `image` на страницу.
Параметры — как в ТЗ: `pages` (по умолчанию первая, не больше 5 за вызов), `dpi` (72–200, по
умолчанию 150), `save_to_export`. Картинка — JPEG с качеством 80, длинная сторона до 1600
пикселей; ответ — не больше 4 МБ картинок, что не поместилось — отдельным вызовом. С
`save_to_export` картинки пишутся в папку выгрузки под именем «номер-имя-стрN.jpg», попадают в
журнал выгрузок и удаляются по тому же сроку; в ответе — пути.

Выключатель — «Показывать агенту страницы вложений картинками» на вкладке «ИИ», по умолчанию
включён: это то же чтение вложений, только в виде картинки.

**Что выяснилось по дороге.** Windows рисует страницу PDF крупнее запрошенного: размер задаётся в
единицах, не зависящих от экрана, и на ноутбуке автора картинка выходила в 1,8 раза больше
запрошенной. Теперь масштаб измеряется первой отрисовкой, и наружу идёт картинка ровно запрошенного
размера. Заодно распознавание читает страницу в настоящих 300 dpi, а не в 424, как выходило
раньше; качество на синтетическом скане осталось тем же (90 % слов точно).

**Где что лежит.** `aiowa_ocr::Pictures` — страница в JPEG (`win.rs`: отрисовка, кадр картинки,
кодировщик с качеством). `mcp_tools::get_attachment_pages` — параметры, пределы, оба режима; ответ
с картинками — `mcp_tools::Rich` и блоки `image` в `mcp.rs`. `export::write_file` — запись картинки
в папку выгрузки. Проба: `cargo run -p aiowa-ocr --example ocr -- <файл> --jpeg <куда>`.

**Тесты** (3 новых, всего 504): страница в JPEG заданного размера, качество, картинка-вложение;
запись своего файла в папку выгрузки; сквозной тест сервера — одна страница, двенадцать страниц
(пять и пометка), 72 dpi, страницы, которых нет, файл без страниц, сохранение в папку, выключатель.

**Живая проверка 23.11.2026** — на копии настоящей базы, проверочный MCP-клиент; картинки страниц
не сохранялись и не просматривались, проверялись формат и размеры:

- скан из ТЗ: блок текста и блок `image`, JPEG 1131×1600, 123 КБ, 0,3 с; в 72 dpi — 595×842, 37 КБ;
- запрошено девять страниц двухстраничного файла — отданы две;
- PDF в четыре страницы — четыре картинки, ответ 0,9 МБ;
- фотография документа — она сама, уменьшенная до 1049×1600;
- таблица Excel — отказ с подсказкой про `get_attachment` и `export_attachment`;
- `save_to_export` без выбранной папки — отказ.

Как выглядит страница для агента, проверено на синтетическом скане: текст, числа в таблице и
печать читаются.

**Не проверено:** видит ли картинки настоящий агент (мост) — это первый же его вызов; флажок в окне
глазами; сохранение в папку выгрузки на настоящих вложениях (только тестом); установленная сборка.
