# Аудит кода перед 0.2.10 (12.11.2026)

Вопрос автора: нет ли в коде мёртвого и лишнего, есть ли что ускорить. Ниже — что смотрели, что
нашли и поправили в 0.2.10, и что отложено с причиной.

## Как смотрели

- Механический проход: команды Tauri без вызова из окна и методы `api.ts` без использования,
  зависимости `Cargo.toml` без единого `use`, проверка TypeScript с `noUnusedLocals`,
  неиспользуемые селекторы и переменные CSS.
- Три независимых прохода по частям: хранилище и синхронизация, бэкенд приложения и транспорт,
  окно (Svelte).
- Замеры на копии настоящей базы: 155 тыс. писем, 112 тыс. бесед. Каждая находка про скорость
  проверялась планом запроса (`EXPLAIN QUERY PLAN`) и временем до и после; что замером не
  подтвердилось — не трогали.

## Что ускорено

| Что | Было | Стало | Как |
|---|---|---|---|
| Открытие беседы (письма и ключ состояния) | ~0,4 с, перебор всего ящика | меньше 1 мс | В базе нет статистики, и планировщик брал индекс по ящику вместо индекса беседы. Запрос подсказывает нужный (`+i.account_id`), тест сверяет план |
| Подсчёт вложений к загрузке, на папку | ~0,85 с | меньше 1 мс | Порядок соединения закреплён (`CROSS JOIN`), та же подсказка |
| Два дозапроса после каждого прогона синхронизации (короткие ключи изменений, метки «отвечено») | по ~0,4 с, после каждого прогона | по частичным индексам и только после полного прогона | Миграция v13: два частичных индекса |
| Поиск `кому:адрес` | ~0,4 с | ~0,05 с | Подзапрос по получателям вместо соединения |
| Открытие композера (свои адреса) | 75 мс на каждое | из памяти, 10 минут | Кэш в приложении; пустой ответ не запоминается |
| Отладочная сборка приложения | лишняя статическая библиотека 1,2 ГБ на каждую сборку | её нет | Из `crate-type` убраны `staticlib` и `cdylib` — они нужны только мобильным сборкам |

Ещё, без замера «до и после», но по делу:

- 20 коротких команд окна (настройки ИИ, журнал, локальный черновик, подпись, напоминания,
  свёрнутые папки, вложения письма) выполнялись в главном потоке окна и ждали там замок базы,
  пока синхронизация пишет пачку писем: окно в это время не двигалось и не перерисовывало
  рамку. Теперь они идут в пуле потоков.
- Ответ сервера разбирается по ссылке, без копии дерева JSON: раньше копировалась каждая пачка
  писем и каждое вложение в base64 (до ~33 МБ).
- Кэш адресатов для подсказок сбрасывается, только когда прогон что-то записал, а не после
  каждого пустого прогона.
- Очистка кэша вложений выходит сразу, если кэш меньше предела, не перебирая файлы.
- Кэш подготовленных запросов SQLite увеличен с 16 до 128: запросов в приложении больше сотни.
- Композер на каждое нажатие дважды переводил тело письма в текст — теперь один раз.
- Миграция v13 убирает два индекса, которыми не пользовался ни один запрос (`items_conversation`,
  `recipients_email`): меньше работы на каждую запись письма.

Гипотеза «поиск медлит из-за отрывков текста для всех совпадений» замером не подтвердилась
(~0,95 с на частое слово и с отрывками, и без) — код поиска оставлен прежним.

## Что убрано

- Команды приложения без вызова из окна: `own_addresses`, `ai_profile_models`,
  `setup_normalize_host`; событие `settings-changed`, которое никто не слушал.
- Зависимости без единого использования: `thiserror` (core), `serde` и `serde_json` (transport),
  `serde` и `thiserror` (transport-owa), `tracing` (cli), `html2text` (весь воркспейс).
- Функции, на которые ссылались только их же тесты: `DraftContent::to_outgoing`,
  `MeetingMessageKind::is_meeting_class`, константа `V_2016`, вторая копия `truncate`,
  `FTS_COLUMNS`, поле `SearchHit.rank`. Функции, нужные только тестам, помечены `#[cfg(test)]`.
- Шесть копий `now_ms` в приложении — осталась одна.
- В окне: методы `api.ts` снятых команд и подписка `onSettingsChanged`; слойный режим просмотра
  вложений (с 0.2.7 просмотр — всегда своё окно); место под кнопки в шапке отдельных окон, куда
  никто ничего не клал; стиль `.avatar` без элемента; семь переменных оформления без ссылок;
  состояние `loading` в «Людях», которое никто не читал; вторая копия склонения по числу.
- Описания, стоявшие не над своей функцией (хранилище, транспорт, приложение), — на месте.

## Что попутно исправлено

- Сохранение и удаление личного контакта и шаги раздела «Хранилище» при оборванной сессии не
  сбрасывали её: следующая команда шла в ту же мёртвую сессию. Теперь сбрасывают, как остальные
  команды; у шагов «Хранилища» появился предел ожидания сервера.
- Локальный черновик: запись и удаление теперь идут строго по очереди, и окно перед закрытием
  ждёт, пока они дойдут до базы. Без этого удаление могло обогнать запись — закрытое письмо
  всплывало бы полосой «Несохранённое письмо».
- Подписка композера на ход синхронизации оставалась навсегда, если композер закрывали раньше,
  чем она оформилась. Таймер подсказки «Адреса скопированы» не снимался при закрытии письма.
- Строка состояния: «21 предупреждений» → «21 предупреждение».
- Настройки: ошибка при удалении доверенного отправителя гасла через 2,5 с как обычное
  «Сохранено» — теперь остаётся.
- Список бесед на окне выше ~1300 px (большой монитор) оставлял пустой низ до первой прокрутки:
  высота списка бралась только при прокрутке.
- Полоса ошибки ложилась поверх полосы «Несохранённое письмо» — теперь встаёт над ней.
- Вкладка «ИИ»: подсказка говорила, что «Совет» ещё не выпущен.

## Что отложено и почему

- **Перечитывание открытой беседы после своей же правки.** После «прочитано», флага, переноса
  окно перечитывает беседу целиком, с телами и картинками, хотя уже показало правку. Дешёвый
  ключ состояния тут не годится: в нём нет папки письма, метки «отвечено» и текста черновика.
  Нужна отметка изменения письма и в ключе, и в письме окна — отдельная работа с проверкой
  всех путей записи.
- **Второе соединение SQLite для чтения.** Соединение одно, чтения окна ждут записей
  синхронизации. WAL позволяет читать параллельно, но это переделка хранилища с риском для
  транзакций — не для патча.
- **Ленивые тела в беседе.** Команда `conversation` отдаёт тела и встроенные картинки всех
  писем, хотя раскрыто обычно одно. Меняет договор окна и бэкенда.
- **Повторы в окне.** Стили кнопок и индикатора (600–1000 строк по компонентам), восемь копий
  ловушки Tab, по три копии «размер словами» и «секунды», ~100 общих строк у главного окна и
  окна письма. Вынос требует визуального прохода по всем экранам.
- **Загрузка окон по требованию** (`import()` для окон письма, черновика, вложений): сборка —
  один файл 533 КБ. Нужна проверка политики CSP на собранном приложении.
- **Сужение CSP и разрешений окон**, **статистика планировщика** (`ANALYZE`; пока запросы
  подсказывают индекс сами), **пропуск переиндексации текста, когда письмо изменилось только
  флагом**.
- **Перечитывание списка берёт не больше 500 бесед**: после прокрутки дальше 500 список при
  обновлении укорачивается. Край, но поведение стоит решить отдельно.

## Проверки

`cargo clippy --workspace --all-targets -- -D warnings` — чисто; тесты воркспейса — без отказов
(к прежним добавлены два теста планов запросов: беседа читается по своему индексу, дозапросы —
по частичным); `svelte-check` — 0 ошибок, 0 предупреждений. Миграция v13 на копии настоящей базы
— 6,5 с в отладочной сборке.

Живая проверка в окне разработки на настоящем ящике (12.11.2026, отладочная сборка):

- миграция v13 на настоящей базе — меньше секунды от запуска до открытого хранилища;
- 40 бесед «Входящих»: ключ состояния — 1,9 мс в среднем (до 4 мс), беседа целиком с телами —
  17,5 мс в среднем (до 126 мс на беседе из 34 писем), вместе с дорогой до окна и обратно;
- поиск `кому:адрес` — 28–59 мс;
- локальный черновик записывается и после «Не сохранять» исчезает; 16 отмен, нацеленных в момент
  срабатывания отложенной записи, — ни одного оставшегося черновика и ни одной полосы
  «Несохранённое письмо»;
- перенос начатого письма в отдельное окно: тема на месте, после закрытия окна локального
  черновика нет;
- окно просмотра вложений после слияния стилей: на всё окно, шапка 40 px, без рамки и тени,
  кнопки окна на месте, Esc закрывает;
- список бесед следует за высотой окна: 741 → 921 px, нарисованных строк 15 → 17;
- ошибок в консоли окон нет, выход из сессии OWA при закрытии выполнен.
