# AIOWA

Офлайн почтовый клиент для корпоративного Exchange в духе Outlook Web App. Rust и Tauri, под Windows.

AIOWA говорит с сервером через тот же внутренний JSON API, что и браузерная OWA: для сервера это обычная сессия OWA, ни EWS, ни IMAP, ни прав администратора не нужно. Почта, календарь и контакты лежат в локальной базе SQLite, поэтому поиск мгновенный, а читать и готовить ответы можно без связи.

## Состояние

Версия 0.2.19 (ноябрь 2026). С 24.10.2026 автор работает в установленной сборке каждый день; замечания и их судьба — в [docs/obkatka.md](docs/obkatka.md). Проверено на Exchange 2019, на других версиях не проверялось.

## Что умеет

- **Почта.** Дерево папок, беседы, чтение; прочитано, флаг, перенос, удаление, архив с окном отмены; выбор нескольких писем, перетаскивание в папки, создание и переименование папок.
- **Письма.** Новое, ответ, ответ всем, пересылка; адресаты с подсказками из справочника организации; вложения из диалога, перетаскиванием и картинкой из буфера; подпись, важность; черновики на сервере и локальный черновик, который переживает сбой и потерю связи.
- **Поиск.** По локальной базе (FTS5), вместе с текстом вложений: PDF, DOCX, XLSX, TXT, CSV. Операторы `от:`, `кому:`, `тема:`, `вложение:`, `папка:`, `после:`, `до:`. Запрос обычным языком («письма от диспетчера про ремонт за октябрь») разбирается без модели, с учётом падежей.
- **Вложения.** Просмотр в окне, открытие, сохранение; вложенные письма.
- **Календарь.** День, рабочая неделя, неделя, месяц; создание и правка встреч, ответы на приглашения, напоминания.
- **Люди.** Личные контакты, справочник организации, карточка контакта.
- **Уведомления.** Новая почта приходит сразу (длинный опрос, как у OWA); уведомление Windows по щелчку открывает письмо.
- **Обновления.** Приложение обновляется само из выпусков GitHub; каждый установщик подписан ключом обновлений.
- **ИИ — по желанию, по умолчанию выключено.** Подключения к моделям (Anthropic, OpenAI-совместимые, свой сервер), «Совет» при ответе, доводка поискового запроса, «Кратко по найденному». Режим «Только свои модели» не пускает письма в облако; журнал обращений ведётся без содержимого.
- **MCP-сервер для ИИ-агентов** — см. ниже.

## Установка

Последний установщик — на [странице выпусков](https://github.com/zergont/AIOWA/releases/latest): `AIOWA_<версия>_x64-setup.exe`.

- Ставится для текущего пользователя, права администратора не нужны. Нужны Windows 10 или 11 (x64; проверено на Windows 11) и WebView2 — если его нет, установщик поставит сам.
- Установщик не подписан сертификатом издателя: SmartScreen покажет «Неизвестный издатель». Следующие версии приходят уже через приложение и проверяются по подписи ключа обновлений.
- Первый запуск — мастер подключения: адрес OWA (как в браузере), логин, пароль и глубина загрузки текстов писем. Список писем всех папок загружается целиком, тексты старше выбранного срока подтягиваются при открытии.

Данные лежат в `%LOCALAPPDATA%\AIOWA`, настройки — в `%APPDATA%\AIOWA\config.json`.

## ИИ-агенты (MCP)

AIOWA умеет работать MCP-сервером: агент на этом же компьютере — Claude Code, Claude Desktop — сам ищет и читает почту из локальной базы. Ему доступны письма и беседы, папки, вложения (текст и файл; чего нет на диске, скачивается с сервера по запросу), календарь и контакты.

По отдельному разрешению агент готовит письма: новое, ответ или пересылку, с файлами и вложениями из других писем. Письмо появляется в окне полосой «Черновик от агента» — отправляете его вы. Отправить, удалить или изменить письмо агент не может.

Доступ выключен по умолчанию и включается в настройках: «ИИ» → «Доступ для агентов (MCP)». Там же выбор видов данных, журнал обращений и готовые строки подключения.

Claude Code:

```
claude mcp add --scope user aiowa -- "<путь к aiowa-desktop.exe>" --mcp
```

Claude Desktop — в `claude_desktop_config.json`, раздел `mcpServers`:

```json
"aiowa": { "command": "<путь к aiowa-desktop.exe>", "args": ["--mcp"] }
```

Сеть AIOWA для этого не открывает: агент сам запускает её с ключом `--mcp` и говорит с ней через stdin и stdout. Помните, что всё прочитанное агентом уходит в его модель, обычно облачную. Устройство и проверки — [docs/ai-layer-design.md](docs/ai-layer-design.md), раздел 11.

## Безопасность

- Пароль хранится в диспетчере учётных данных Windows. Cookies сессии OWA живут только в памяти, при выходе сессия на сервере закрывается.
- HTML письма очищается и показывается в изолированном фрейме без скриптов; внешние картинки и шрифты не загружаются.
- Журнал приложения не содержит текста писем, адресов, имён вложений и токенов сессии.
- Окно не ходит в сеть само: все запросы к серверу и к моделям идут из Rust.

Подробнее — [apps/desktop/README.md](apps/desktop/README.md) и [CONCEPT.md](CONCEPT.md).

## Структура

```
apps/desktop                окно: Tauri 2 (Rust, WebView2) + Svelte 5 + TypeScript; MCP-сервер
crates/aiowa-core           доменные типы
crates/aiowa-transport      trait транспорта и модель ошибок
crates/aiowa-transport-owa  реализация поверх OWA JSON (reqwest, системный TLS)
crates/aiowa-store          SQLite: схема, миграции, FTS5, беседы, кэш вложений
crates/aiowa-extract        текст из вложений: PDF, DOCX, XLSX, TXT/CSV
crates/aiowa-sync           движок синхронизации
crates/aiowa-ai             шлюз моделей, «Совет», подготовка текста писем для моделей
crates/aiowa-cli            консольная утилита `aiowa` для проб и полных прогонов
spike/owa-probe             спайк протокола, источник форм запросов
docs/                       план, протокол, проекты, замечания обкатки, заметки выпусков
```

## Сборка из исходников

Нужны Rust stable (rustc 1.90 или новее) и Node.js 22.

```powershell
cd apps\desktop
npm install
npx.cmd tauri dev      # окно разработки
npx.cmd tauri build    # установщик; нужен ключ обновлений, см. apps/desktop/README.md
```

Проверки, те же, что в CI:

```powershell
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cd apps\desktop
npm run check
npm run build
```

Консольная утилита — для проб протокола и полных прогонов синхронизации:

```bash
cargo build -p aiowa-cli
./target/debug/aiowa --host mail.example.com --user 'user@domain' set-password
./target/debug/aiowa --host mail.example.com --user 'user@domain' sync --days 90
./target/debug/aiowa --host mail.example.com --user 'user@domain' search "запчасти колыма от:петров после:2026-09 вложение:"
```

`--host` и `--user` можно задать переменными `AIOWA_HOST` и `AIOWA_USER`.
