# AIOWA Desktop

Окно почты поверх локальной базы SQLite: дерево папок, список бесед, область чтения, поиск.
Синхронизацию с сервером приложение запускает само (строка состояния внизу окна); `aiowa sync`
из консоли остаётся для проб и полных прогонов с нестандартными ключами.

Стек: Tauri 2 (Rust, WebView2) + Svelte 5 + Vite 8 + TypeScript.

## Запуск в разработке

```powershell
cd apps\desktop
npm install
$env:AIOWA_HOST = 'mail.ngenergo.ru'
$env:AIOWA_USER = 'login@domain'
npx.cmd tauri dev
```

Переменные окружения:

| Переменная   | Назначение                                                                 |
|--------------|----------------------------------------------------------------------------|
| `AIOWA_HOST` | Хост OWA, по нему и логину выбирается учётная запись в базе                |
| `AIOWA_USER` | Логин, как при `aiowa sync`                                                |
| `AIOWA_DB`   | Явный путь к `mail.db`; по умолчанию `%LOCALAPPDATA%\AIOWA\<host>\<user>\mail.db` |

`npx.cmd` вместо `npx`: в Windows PowerShell с политикой Restricted скрипт `npx.ps1` не запускается.

Если на машине несколько установок Rust, укажи ту, где стоит toolchain проекта (нужен rustc ≥ 1.90):

```powershell
$env:RUSTUP_HOME = 'D:\rust\rustup'
$env:CARGO_HOME  = 'D:\rust\cargo'
```

## Синхронизация из окна

- Пароль берётся из диспетчера учётных данных Windows (служба `AIOWA`, ключ = логин), как у CLI:
  перед первым запуском выполни `aiowa --host … --user … set-password`. Формы ввода пароля в окне нет;
  без пароля строка состояния покажет ошибку с этой подсказкой.
- Одна сессия OWA на процесс: вход при первой синхронизации, `logoff.owa` при закрытии окна
  (при жёстком завершении процесса, например при пересборке `tauri dev`, сессия на сервере остаётся
  до истечения; лимит сервера около 10 сессий).
- Запуск: автоматически при старте, затем раз в 2 минуты при видимом окне, и по кнопке «Обновить».
  Повторный запуск, пока идёт предыдущий, не делается. «Остановить» прерывает после текущей пачки.
- Что синхронизируется: все почтовые папки (как `--folders all`), тела и вложения за 90 дней
  (`sync_start { days }` позволяет задать иное окно; 0 = без ограничения).
- Одна папка: кнопка со стрелкой появляется при наведении на строку дерева и запускает
  `sync_start { folders: [folder_pk] }` только для неё. Так подтягиваются служебные папки, которых
  нет в общем наборе (нежелательная, удалённые, черновики); раз синхронизированная папка дальше
  обновляется вместе со всеми (`folders_for_sync` включает папки с состоянием синхронизации).
- Команды: `sync_start`, `sync_status`, `sync_cancel`; ход приходит событием `sync-progress`
  (структура `SyncStatus` в `src/lib/api.ts`). Время последней успешной синхронизации хранится в базе
  (`sync_state`, ключ `desktop.last_sync_ok_ms`) и показывается после перезапуска.
- После завершения окно перечитывает папки, текущий список бесед и открытую беседу, не сбивая выбор.

## Тела и вложения по требованию

Синхронизация грузит тела и вложения только за окно `--days`; остальное окно догружает само,
когда пользователь открывает письмо (`src-tauri/src/ondemand.rs`). Сеть идёт через тот же
транспорт процесса, что и синхронизация: новых входов на сервер эти команды не делают.

- `message_fetch(item_pk)` — тело письма (если `body_state` 0 или 2) и инлайновые картинки без
  файла в кэше (по одной, до 8 МиБ каждая); возвращает DTO письма, где `src="cid:…"` уже заменены
  на `data:`-URI (суммарно до 16 МиБ на письмо, несопоставленные `cid:` теряют `src`).
  Карточка вызывает команду сама при раскрытии, показывает «Загружаю письмо с сервера…» и ошибку
  с кнопкой «Повторить». Повторный вызов без изменений в сеть не ходит.
- `attachment_open(attachment_pk)` — скачивает файл в кэш (`<каталог mail.db>\attachments`, лимит
  200 МиБ), ставит метку зоны «Интернет» (`Zone.Identifier`) и открывает системным приложением
  через ShellExecute. Исполняемые и скриптовые расширения (`.exe`, `.js`, `.lnk`, `.msi`…) не
  открываются — только «Сохранить как…».
- `attachment_save_as(attachment_pk)` — тот же файл копируется туда, куда укажет диалог
  «Сохранить как» (по умолчанию папка «Загрузки»); копия тоже получает метку зоны. Возвращает путь
  или `null` при отмене.
- `open_external(url)` — ссылки из письма открываются во внешнем браузере или почтовой программе;
  разрешены только `http`, `https`, `mailto`. Клик по ссылке внутри фрейма перехватывается и уходит
  сюда, сам фрейм никуда не переходит.
- `conversation_key(conversation_pk)` — дешёвый ключ состояния беседы; после синхронизации окно
  перечитывает беседу только при расхождении ключа.

Ошибки команд приходят строками по-русски и показываются в карточке письма, не в общей полосе
ошибок. Отказ сервера по телу записывается как `body_state = 2`; истёкшая сессия, отклонённый вход
и сеть в базу не пишутся, а сбрасывают транспорт процесса (следующий вызов войдёт заново).

## Действия с письмами (запись на сервер)

`src-tauri/src/write.rs`: `items_mark_read`, `items_set_flag`, `items_move`, `items_delete`,
`conversation_item_pks`. Порядок у каждой команды один: изменение сразу применяется в локальной
базе (окно видит результат мгновенно), затем уходит на сервер через транспорт процесса
(UpdateItem, MoveItem, DeleteItem; формы в `docs/protocol-owa-json.md` § 5e) пачками по 25;
отказ сервера по письму откатывает его локальное изменение и возвращается в `failed` с русским
текстом, отказ всего вызова откатывает всё, что сервер не подтвердил. `ErrorItemNotFound`
не откатывается: письма на сервере уже нет, строка помечается удалённой до следующей
синхронизации. В конце команда шлёт событие `items-changed { conversation_pks, folder_pks }`,
и окно перечитывает открытую беседу, список бесед и счётчики папок.

- Удаление: `permanent = false` переносит в «Удалённые» (локально тоже перенос); письмо, уже
  лежащее там, не трогается. `permanent = true` удаляет навсегда, в окне только с подтверждением.
- В окне: панель действий в шапке развёрнутого письма (прочитано/непрочитано, флаг, переместить,
  удалить), контекстное меню беседы в списке (правая кнопка, Shift+F10), клавиша Delete,
  Shift+Delete — навсегда с подтверждением. Непрочитанное письмо, развёрнутое и видимое 1,5 с,
  помечается прочитанным само (как в OWA); ручное «непрочитано» этот таймер гасит.
- Один замок на операции записи в процессе; синхронизация идёт параллельно, следующий проход
  сверяет локальное состояние с сервером.
- Из консоли то же: `aiowa mark-read`, `flag`, `move`, `delete` (перенос и удаление требуют
  `--yes-i-know`).

## Ответ, пересылка, новое письмо

`src-tauri/src/compose.rs` и `src/lib/components/Composer.svelte`. Отправка идёт в три шага через
транспорт процесса: `CreateItem` (черновик в «Черновиках», для ответа и пересылки это
`ReplyToItem` / `ReplyAllToItem` / `ForwardItem`, цитату оригинала и его вложения добавляет
сервер) → `CreateAttachment` по файлу → `SendItem` с копией в «Отправленные». Формы в
`docs/protocol-owa-json.md` § 5f, проверены на сервере.

- Точки входа: «Новое письмо» слева от поиска и Ctrl+N; на карточке письма «Ответить»,
  «Ответить всем», «Переслать» и Ctrl+R, Ctrl+Shift+R, Ctrl+Shift+F; те же пункты в контекстном
  меню беседы. Композер ответа встаёт над карточками беседы, новое письмо занимает область чтения.
- Получатели: чипы с автодополнением по адресам из локальной базы (`recipients_suggest`, кэш в
  памяти), вставка нескольких адресов, проверка формата. «Ответить всем» исключает собственные
  адреса (`own_addresses`: самые частые отправители в «Отправленных» плюс логин). Явно
  опустошённое поле «Копия» на сервере остаётся пустым (проверено на черновике).
- Редактор: contenteditable с панелью форматирования; тело перед отправкой проходит ту же очистку
  ammonia, что показ писем. Подпись хранится локально (`desktop.signature_html`), кнопка «Взять из
  OWA» читает её из настроек OWA (`GetUserConfiguration OWA.UserOptions`).
- Вложения: до 25 МиБ на файл и 35 МиБ вместе, выбор через системный диалог.
- Исходы `compose_send`: `sent` — ушло; `draft_saved` — черновик остался на сервере, повтор создаст
  второй; `maybe_sent` — ответа на `SendItem` не было, письмо могло уйти, «Повторить» не
  предлагается. Один замок на отправку: второй Ctrl+Enter получает «Отправка уже идёт».
- После отправки окно запускает синхронизацию «Отправленных». Закрытие окна с незаконченным
  письмом спрашивает подтверждение.
- Из консоли: `aiowa send --to … --subject … --body … [--attach …] --yes-i-know`, `signature`,
  `suggest <префикс>`.

## Календарь

Переключатель «Почта / Календарь» в верхней панели (Ctrl+Shift+1 / Ctrl+Shift+2). В режиме
календаря слева мини-календарь месяца, в центре сетка дня, рабочей недели или недели (клавиши
D / W / Shift+W, ← → листают период, T — сегодня), справа карточка события.

- События берутся запросом `FindItem` с календарным окном (`CalendarPageView`): повторяющиеся
  встречи сервер сам разворачивает в экземпляры. Формы в `docs/protocol-owa-json.md` § 5g.
- Кэш в базе (`calendar_items`, `calendar_ranges`, схема v4): `calendar_events(start_ms, end_ms,
  refresh)` без `refresh` отдаёт только кэш (мгновенно и без сети), окно само запрашивает
  обновление фоном, если окно не покрыто или старше 5 минут, и раз в 5 минут, пока календарь
  виден. При ошибке сети показывается кэш и текст ошибки.
- Карточка события: `calendar_event_details(calendar_pk, refresh)` — участники с ответами,
  напоминание, текст повторения (у экземпляров через `GetItem` мастера), тело в том же фрейме,
  что и письма.
- События на весь день приходят как полуночи организатора в UTC; день показа — местная дата
  ближайшей полуночи (разница поясов до 12 часов).
- Из консоли: `aiowa calendar --from YYYY-MM-DD --to YYYY-MM-DD [--details N]`.

## Мгновенные обновления и уведомления

`src-tauri/src/notify.rs` поверх канала OWA (`docs/protocol-owa-json.md` § 4 и § 5h). После первой
удачной синхронизации фоновая задача подписывается (`SubscribeToNotification`) на строки всех
синхронизируемых папок, новую почту, дерево папок и календарь и держит открытым поток
`/owa/ev.owa2`; цикл потока сервер закрывает примерно через 5 минут, клиент завершает его
`FinishNotificationRequest` и открывает следующий. Идентификаторы подписок постоянны на время
жизни процесса, поэтому повторная подписка в той же сессии не плодит дублей.

- По событиям строк папки синхронизируются только затронутые папки (дебаунс 1,5 с, очередь, если
  синхронизация уже идёт); изменение дерева — синхронизация папки или полный прогон.
- Новая непрочитанная почта — уведомление Windows (tauri-plugin-notification): не чаще одного в
  5 секунд, при лавине одна сводка «N новых писем». Переключатель в строке состояния (колокольчик),
  ключ `desktop.notify_toasts`.
- Заголовок окна «AIOWA (N)» и значок на панели задач показывают непрочитанные во «Входящих»;
  обновляются после синхронизации и после действий из окна.
- Индикатор канала в строке состояния: «мгновенные обновления» или «по таймеру»; при живом канале
  страховочная синхронизация по таймеру идёт раз в 10 минут вместо 2.
- Счётчик непрочитанных через подписку Unseen этот сервер не отдаёт (нужен Broker), поэтому число
  берётся из локальной базы.
- Из консоли: `aiowa notify --seconds N [--folders inbox,…]` печатает виды событий и счётчики.

## Структура

- `src/App.svelte` — три панели, строка поиска и строка состояния; выбранная папка/беседа;
  автозапуск синхронизации и обновление списков после неё.
- `src/lib/components/` — `FolderTree`, `ConversationList` (виртуализация строк), `ReadingPane`,
  `MessageCard` (письмо в `iframe sandbox` с CSP), `SearchResults`, `StatusBar` (кнопка «Обновить»,
  ход, время последней синхронизации, ошибки).
- `src/lib/api.ts` — типы DTO, обёртки `invoke` над командами Tauri и подписка `onSyncProgress`.
- `src/tokens.css` — дизайн-токены (светлая/тёмная тема, Fluent-подобные).
- `src-tauri/src/lib.rs` — команды `account_info`, `folders`, `conversations`, `conversation`, `search`;
  очистка HTML через ammonia; выход из сессии OWA при закрытии.
- `src-tauri/src/sync.rs` — состояние синхронизации, транспорт OWA процесса, команды `sync_*`,
  событие `sync-progress`.
- `src-tauri/src/ondemand.rs` — команды `message_fetch`, `attachment_open`, `attachment_save_as`,
  `open_external`; замки по письму и вложению, таймауты, тексты ошибок.
- `src-tauri/src/write.rs` — команды записи `items_*`, оптимистичное применение и откат, событие
  `items-changed`.
- `src/lib/components/FolderPicker.svelte`, `ContextMenu.svelte`, `ConfirmPopover.svelte` —
  всплывающие окна действий; `src/lib/actions.ts`, `src/lib/popover.ts` — их общая логика.

## Безопасность отображения писем

HTML письма очищается на стороне Rust (ammonia: без скриптов, обработчиков событий и
`javascript:`), затем показывается в `<iframe sandbox="allow-same-origin" srcdoc>` с
`Content-Security-Policy: default-src 'none'; img-src data:; style-src 'unsafe-inline'`.
Внешние картинки и шрифты не загружаются вообще; инлайновые картинки письма приходят из кэша
вложений как `data:`-URI, подстановка делается в Rust при очистке (`attribute_filter` ammonia).
