# AIOWA Desktop

Окно почты поверх локальной базы SQLite: дерево папок, список бесед, область чтения, поиск.
Синхронизацию с сервером приложение запускает само (строка состояния внизу окна); `aiowa sync`
из консоли остаётся для проб и полных прогонов с нестандартными ключами.

Стек: Tauri 2 (Rust, WebView2) + Svelte 5 + Vite 8 + TypeScript.

## Запуск в разработке

```powershell
cd apps\desktop
npm install
$env:AIOWA_HOST = 'mail.ngenergo.ru'
$env:AIOWA_USER = 'login@domain'
npx.cmd tauri dev
```

Переменные окружения:

| Переменная   | Назначение                                                                 |
|--------------|----------------------------------------------------------------------------|
| `AIOWA_HOST` | Хост OWA, по нему и логину выбирается учётная запись в базе                |
| `AIOWA_USER` | Логин, как при `aiowa sync`                                                |
| `AIOWA_DB`   | Явный путь к `mail.db`; по умолчанию `%LOCALAPPDATA%\AIOWA\<host>\<user>\mail.db` |
| `AIOWA_CONFIG_DIR` | Каталог `config.json` вместо `%APPDATA%\AIOWA`, см. «Первый запуск и настройки» |

Без `AIOWA_HOST` и `AIOWA_USER` учётная запись берётся из `config.json`, а если её нет — окно
открывает мастер подключения.

`npx.cmd` вместо `npx`: в Windows PowerShell с политикой Restricted скрипт `npx.ps1` не запускается.

Если на машине несколько установок Rust, укажи ту, где стоит toolchain проекта (нужен rustc ≥ 1.90):

```powershell
$env:RUSTUP_HOME = 'D:\rust\rustup'
$env:CARGO_HOME  = 'D:\rust\cargo'
```

## Первый запуск и настройки

Учётная запись берётся в таком порядке: переменные `AIOWA_HOST` и `AIOWA_USER` (разработка), затем
`%APPDATA%\AIOWA\config.json`, иначе окно открывается мастером подключения. Каталог конфигурации
меняет переменная `AIOWA_CONFIG_DIR`: пустой каталог — способ посмотреть мастер на машине, где
учётная запись уже настроена.

```powershell
$env:AIOWA_HOST = ''; $env:AIOWA_USER = ''
$env:AIOWA_CONFIG_DIR = 'D:\projects\AIOWA\target2\setup-test'
npx.cmd tauri dev
```

Мастер в три шага:

1. **Сервер.** Принимает адрес из браузера (`https://mail.example.ru/owa/`), имя сервера или
   `сервер:порт`; адрес почты вместо сервера отклоняется с подсказкой.
2. **Учётная запись.** Логин в виде `user@domain` или `ДОМЕН\user`, пароль. «Проверить вход»
   входит отдельной сессией и сразу выходит; «Далее» без проверки сначала проверяет.
3. **Синхронизация.** Глубина загрузки тел писем (30 дней, 90 дней, год, всё) и запуск первой
   синхронизации. «Готово» пишет `config.json`, кладёт пароль в диспетчер учётных данных Windows
   (запись «AIOWA») и перезапускает приложение в режиме почты.

Если база не открылась (повреждена, нет доступа), приложение тоже открывает мастер и показывает
причину.

Окно настроек открывается шестерёнкой в шапке или Ctrl+, откуда угодно, в том числе из редактора
письма. Вкладки:

| Вкладка        | Что настраивается                                                                 |
|----------------|-----------------------------------------------------------------------------------|
| Учётная запись | Смена пароля: сначала проверка входа, потом замена в диспетчере. «Забыть учётную запись»: пароль и запись из `config.json` удаляются, база остаётся, приложение перезапускается в мастер. При учётной записи из переменных окружения недоступно |
| Синхронизация  | Глубина загрузки тел, интервал страховочной синхронизации                         |
| Чтение         | Автопометка прочитанным: не помечать, сразу, через 1,5 с или 5 с                   |
| Уведомления    | Уведомления Windows о новых письмах; тот же переключатель — колокольчик в строке состояния |
| Подпись        | Подпись из OWA                                                                    |
| Вид            | Тема: как в Windows, светлая, тёмная (заголовок окна следует теме)                 |
| Данные         | Путь и размер базы, размер кэша вложений, квота кэша, лимит вложения для синхронизации, «Открыть папку» |

Значения лежат в базе (`sync_state`, ключи `desktop.*`). Команда `settings_set` проверяет весь
патч до записи: неизвестное поле или значение вне диапазона отклоняются целиком. После записи
бэкенд шлёт событие `settings-changed`. Тема дублируется в `localStorage`, чтобы окно не мигало
системной темой до ответа `settings_get`.

## Синхронизация из окна

- Пароль берётся из диспетчера учётных данных Windows (служба `AIOWA`, ключ = логин), как у CLI:
  перед первым запуском выполни `aiowa --host … --user … set-password`. Формы ввода пароля в окне нет;
  без пароля строка состояния покажет ошибку с этой подсказкой.
- Одна сессия OWA на процесс: вход при первой синхронизации, `logoff.owa` при закрытии окна
  (при жёстком завершении процесса, например при пересборке `tauri dev`, сессия на сервере остаётся
  до истечения; лимит сервера около 10 сессий).
- Запуск: автоматически при старте, затем раз в 2 минуты при видимом окне, и по кнопке «Обновить».
  Повторный запуск, пока идёт предыдущий, не делается. «Остановить» прерывает после текущей пачки.
- Что синхронизируется: все почтовые папки (как `--folders all`), тела и вложения за 90 дней
  (`sync_start { days }` позволяет задать иное окно; 0 = без ограничения).
- Одна папка: кнопка со стрелкой появляется при наведении на строку дерева и запускает
  `sync_start { folders: [folder_pk] }` только для неё. Так подтягиваются служебные папки, которых
  нет в общем наборе (нежелательная, удалённые, черновики); раз синхронизированная папка дальше
  обновляется вместе со всеми (`folders_for_sync` включает папки с состоянием синхронизации).
- Команды: `sync_start`, `sync_status`, `sync_cancel`; ход приходит событием `sync-progress`
  (структура `SyncStatus` в `src/lib/api.ts`). Время последней успешной синхронизации хранится в базе
  (`sync_state`, ключ `desktop.last_sync_ok_ms`) и показывается после перезапуска.
- После завершения окно перечитывает папки, текущий список бесед и открытую беседу, не сбивая выбор.
- **Живое окно.** Окно не ждёт конца прогона: движок сообщает о каждой записи в базу
  (`SyncEvent::FoldersApplied` — дерево, `SyncEvent::ItemsApplied` — свежая страница или пачка
  `SyncFolderItems` с изменениями), бэкенд (`src-tauri/src/live.rs`) передаёт их окну с
  прореживанием — не чаще раза в 2,5 с на тип события, накопленное за паузу уходит отложенной
  отправкой, последнее не теряется: `folders-changed` после дерева и `sync-live { folders,
  folder_pks }` после писем. Окно (`App.svelte`, `liveRefresh`) мягко перечитывает дерево и
  счётчики, открытый список (если его папка в `folder_pks`) и открытую беседу (только если её
  дешёвый ключ изменился): выбор, раскрытые письма, множественный выбор остаются, прокрутку держит
  список — верхняя видимая строка стоит на месте, даже когда выше неё добавились беседы (в самом
  начале списка новые беседы просто появляются сверху). Пока идёт команда записи (прочитано,
  флаг, перенос, удаление, отмена), загрузка списка, отправка или открытие черновика, обновление
  ждёт; беседа под открытым композером не перечитывается. При первом запуске «Входящие»
  открываются, как только пришло дерево, а «Папок ещё нет» и «В этой папке пока нет бесед» уходят
  сами, как только появились данные. Полное перечитывание — по концу прогона, как раньше.
- **Свежие письма первыми.** У папки, которая синхронизируется впервые (нет состояния
  `SyncFolderItems`), движок сначала берёт последние 100 писем по дате получения (`FindItem`,
  docs/protocol-owa-json.md § 5m) — по всем таким папкам, «Входящие» первыми, — и только потом
  ведёт полные выгрузки. Строка состояния показывает этап «Свежие письма». Полная выгрузка присылает
  те же письма с теми же идентификаторами и ложится поверх без дублей (тело, открытое за это время,
  сохраняется); письмо свежей страницы, которого полная выгрузка так и не прислала, к её концу
  сверяется с сервером и помечается удалённым, только если сервер его больше не знает (удалено или
  перенесено за время выгрузки).
- **Работа во время синхронизации.** Синхронизация занимает одно из двух разрешений транспорта (запросы
  к серверу идут по одному), второе остаётся окну: тело письма по требованию, ответ, перенос и пометки
  не ждут конца прогона (тесты `window_actions_do_not_wait_for_running_sync` в `aiowa-sync` и
  `window_requests_pass_while_sync_request_is_pending` в `aiowa-transport-owa`). Чтения базы, которые
  окно делает и во время прогона (`folders`, `conversations`, `conversation_key`, `search`,
  `conversation_item_pks`), идут не в главном потоке (`#[tauri::command(async)]`): пока движок пишет
  пачку, ждёт только сам запрос, а не всё окно.

## Тела и вложения по требованию

Синхронизация грузит тела и вложения только за окно `--days`; остальное окно догружает само,
когда пользователь открывает письмо (`src-tauri/src/ondemand.rs`). Сеть идёт через тот же
транспорт процесса, что и синхронизация: новых входов на сервер эти команды не делают.

- `message_fetch(item_pk)` — тело письма (если `body_state` 0 или 2) и инлайновые картинки без
  файла в кэше (по одной, до 8 МиБ каждая); возвращает DTO письма, где `src="cid:…"` уже заменены
  на `data:`-URI (суммарно до 16 МиБ на письмо, несопоставленные `cid:` теряют `src`).
  Карточка вызывает команду сама при раскрытии, показывает «Загружаю письмо с сервера…» и ошибку
  с кнопкой «Повторить». Повторный вызов без изменений в сеть не ходит.
- `attachment_open(attachment_pk)` — скачивает файл в кэш (`<каталог mail.db>\attachments`, лимит
  200 МиБ), ставит метку зоны «Интернет» (`Zone.Identifier`) и открывает системным приложением
  через ShellExecute. Исполняемые и скриптовые расширения (`.exe`, `.js`, `.lnk`, `.msi`…) не
  открываются — только «Сохранить как…».
- `attachment_save_as(attachment_pk)` — тот же файл копируется туда, куда укажет диалог
  «Сохранить как» (по умолчанию папка «Загрузки»); копия тоже получает метку зоны. Возвращает путь
  или `null` при отмене.
- `attachment_preview_url(attachment_pk)` — предпросмотр вложения в окне (`src-tauri/src/preview.rs`,
  `AttachmentPreview.svelte`): при необходимости скачивает файл в кэш и возвращает `PreviewDto`
  с адресом протокола `aiowa-att` (`http://aiowa-att.localhost/<attachment_pk>`). Протокол отдаёт
  только файлы кэша вложений текущей учётной записи по целому ключу (иначе 404), без кэширования
  и с `nosniff`; HTML и CSV идут как простой текст. Предпросматриваются картинки, PDF, `text/plain`,
  CSV и HTML (как текст, без выполнения); ←/→ листают вложения письма, остальные типы по клику
  открываются приложением, как раньше.
- `open_external(url)` — ссылки из письма открываются во внешнем браузере или почтовой программе;
  разрешены только `http`, `https`, `mailto`. Клик по ссылке внутри фрейма перехватывается и уходит
  сюда, сам фрейм никуда не переходит.
- `conversation_key(conversation_pk)` — дешёвый ключ состояния беседы; после синхронизации окно
  перечитывает беседу только при расхождении ключа.

Ошибки команд приходят строками по-русски и показываются в карточке письма, не в общей полосе
ошибок. Отказ сервера по телу записывается как `body_state = 2`; истёкшая сессия, отклонённый вход
и сеть в базу не пишутся, а сбрасывают транспорт процесса (следующий вызов войдёт заново).

## Действия с письмами (запись на сервер)

`src-tauri/src/write.rs`: `items_mark_read`, `items_set_flag`, `items_move`, `items_delete`,
`conversation_item_pks`. Порядок у каждой команды один: изменение сразу применяется в локальной
базе (окно видит результат мгновенно), затем уходит на сервер через транспорт процесса
(UpdateItem, MoveItem, DeleteItem; формы в `docs/protocol-owa-json.md` § 5e) пачками по 25;
отказ сервера по письму откатывает его локальное изменение и возвращается в `failed` с русским
текстом, отказ всего вызова откатывает всё, что сервер не подтвердил. `ErrorItemNotFound`
не откатывается: письма на сервере уже нет, строка помечается удалённой до следующей
синхронизации. В конце команда шлёт событие `items-changed { conversation_pks, folder_pks }`,
и окно перечитывает открытую беседу, список бесед и счётчики папок.

- Удаление: `permanent = false` переносит в «Удалённые» (локально тоже перенос); письмо, уже
  лежащее там, не трогается. `permanent = true` удаляет навсегда, в окне только с подтверждением.
- В окне: панель действий в шапке развёрнутого письма (прочитано/непрочитано, флаг, переместить,
  удалить), контекстное меню беседы в списке (правая кнопка, Shift+F10), клавиша Delete,
  Shift+Delete — навсегда с подтверждением. Непрочитанное письмо, развёрнутое и видимое 1,5 с,
  помечается прочитанным само (как в OWA); ручное «непрочитано» этот таймер гасит.
- Один замок на операции записи в процессе; синхронизация идёт параллельно, следующий проход
  сверяет локальное состояние с сервером.
- Из консоли то же: `aiowa mark-read`, `flag`, `move`, `delete` (перенос и удаление требуют
  `--yes-i-know`).

## Ответ, пересылка, новое письмо

`src-tauri/src/compose.rs` и `src/lib/components/Composer.svelte`. Отправка идёт в три шага через
транспорт процесса: `CreateItem` (черновик в «Черновиках», для ответа и пересылки это
`ReplyToItem` / `ReplyAllToItem` / `ForwardItem`, цитату оригинала и его вложения добавляет
сервер) → `CreateAttachment` по файлу → `SendItem` с копией в «Отправленные». Формы в
`docs/protocol-owa-json.md` § 5f, проверены на сервере.

- Точки входа: «Новое письмо» слева от поиска и Ctrl+N; на карточке письма «Ответить»,
  «Ответить всем», «Переслать» и Ctrl+R, Ctrl+Shift+R, Ctrl+Shift+F; те же пункты в контекстном
  меню беседы. Композер ответа встаёт над карточками беседы, новое письмо занимает область чтения.
- Получатели: чипы с автодополнением по адресам из локальной базы (`recipients_suggest`, кэш в
  памяти), вставка нескольких адресов, проверка формата. «Ответить всем» исключает собственные
  адреса (`own_addresses`: самые частые отправители в «Отправленных» плюс логин). Явно
  опустошённое поле «Копия» на сервере остаётся пустым (проверено на черновике).
- Редактор: contenteditable с панелью форматирования; тело перед отправкой проходит ту же очистку
  ammonia, что показ писем. Подпись хранится локально (`desktop.signature_html`), кнопка «Взять из
  OWA» читает её из настроек OWA (`GetUserConfiguration OWA.UserOptions`).
- Вложения: до 25 МиБ на файл и 35 МиБ вместе, выбор через системный диалог.
- Исходы `compose_send`: `sent` — ушло; `draft_saved` — черновик остался на сервере, повтор создаст
  второй; `maybe_sent` — ответа на `SendItem` не было, письмо могло уйти, «Повторить» не
  предлагается. Один замок на отправку: второй Ctrl+Enter получает «Отправка уже идёт».
- После отправки окно запускает синхронизацию «Отправленных» и «Черновиков». Закрытие окна с
  незаконченным письмом спрашивает подтверждение.
- Черновики: «Черновики» синхронизируются по умолчанию. Композер автосохраняет письмо через 30 с
  после последней правки и не чаще раза в 60 с (`compose_autosave`: первый раз `CreateItem`, потом
  `UpdateItem`; вложения не трогает), в подвале «Сохраняю…» / «Черновик сохранён в HH:MM».
  «Сохранить черновик» и Ctrl+S (`compose_save_draft`) пишут и вложения: новые файлы, удаление
  убранных. «Отмена» с правками (и замена композера другим письмом, и закрытие окна) спрашивает:
  сохранить, закрыть без сохранения (у черновика на сервере), удалить (`compose_discard_draft`:
  в «Удалённые») или вернуться. В «Черновиках» карточка показывает «Открыть черновик» (также
  двойной клик и Enter в списке): `compose_open_draft` берёт текст из базы, а если полного тела
  нет — читает `GetItem` с сервера (обрезанный сервером черновик не открывается). Картинки `cid:`
  в редакторе показываются из кэша, исходные `src` и стили возвращаются перед сохранением.
  Отправка открытого или автосохранённого черновика идёт по нему (`draft_server_id`):
  `UpdateItem` → новые файлы → `DeleteAttachment` для убранных (`removed_attachment_ids`, после
  сверки с сервером) → `SendItem`; отказ возвращает черновик окну, второй не создаётся.
  `UpdateItem` заменяет тело целиком, поэтому у ответа и пересылки цитата оригинала при обновлении
  собирается заново (`quote_html`) из полного тела оригинала с сервера (`ItemNormalizedBody`),
  ссылки `cid:` остаются как есть.
- Печать: «Печать» на карточке и Ctrl+P печатают развёрнутое письмо (шапка и очищенное тело)
  через скрытый фрейм и `window.print()` (`src/lib/print.ts`).
- Из консоли: `aiowa send --to … --subject … --body … [--attach …] --yes-i-know`, `signature`,
  `suggest <префикс>`.

## Календарь

Переключатель «Почта / Календарь» в верхней панели (Ctrl+Shift+1 / Ctrl+Shift+2). В режиме
календаря слева мини-календарь месяца, в центре сетка дня, рабочей недели или недели (клавиши
D / W / Shift+W, ← → листают период, T — сегодня), справа карточка события.

- События берутся запросом `FindItem` с календарным окном (`CalendarPageView`): повторяющиеся
  встречи сервер сам разворачивает в экземпляры. Формы в `docs/protocol-owa-json.md` § 5g.
- Кэш в базе (`calendar_items`, `calendar_ranges`, схема v4): `calendar_events(start_ms, end_ms,
  refresh)` без `refresh` отдаёт только кэш (мгновенно и без сети), окно само запрашивает
  обновление фоном, если окно не покрыто или старше 5 минут, и раз в 5 минут, пока календарь
  виден. При ошибке сети показывается кэш и текст ошибки.
- Карточка события: `calendar_event_details(calendar_pk, refresh)` — участники с ответами,
  напоминание, текст повторения (у экземпляров через `GetItem` мастера), тело в том же фрейме,
  что и письма.
- События на весь день приходят как полуночи организатора в UTC; день показа — местная дата
  ближайшей полуночи (разница поясов до 12 часов).
- Из консоли: `aiowa calendar --from YYYY-MM-DD --to YYYY-MM-DD [--details N]`.

Запись (`src-tauri/src/calendar_write.rs`, формы в § 5i протокола):

- «Новая встреча» в панели инструментов, клавиша N, двойной клик по сетке (30 минут от места
  клика) или по строке «весь день»; «Изменить» и «Удалить» в карточке события. Редактор: тема,
  весь день, начало и конец, место, участники с автодополнением, напоминание, занятость, частное,
  описание. При участниках приглашения отправляет сервер (`SendMeetingInvitations`); при правке
  встречи с участниками окно спрашивает, слать ли обновление; при удалении своей встречи с
  участниками — слать ли отмену. У чужих встреч рассылки не делаются.
- `CreateItem`/`UpdateItem` событий идут в часовом поясе пользователя из настроек OWA
  (`OWA.UserOptions`, ключ `timezone`; кэш в `sync_state` под `desktop.owa_timezone` на сутки,
  берётся при обращении к календарю и перечитывается, когда устарел, — так смена пояса в OWA
  подхватывается сама): событие ложится в его пояс, как в браузерной OWA. Границы
  «весь день» в коде кодируются полуночами UTC календарных дат, а на сервер уходят местными
  полуночами без зоны; место передаётся объектом `EnhancedLocation` с `DisplayName` (пустое —
  снять) и читается через `calendar:EnhancedLocation`; занятость в запросах — ключ
  `FreeBusyType`; у UpdateItem для встреч нужен член `SendCalendarInvitationsOrCancellations`.
- Приглашения в письмах (`IPM.Schedule.Meeting.Request`): баннер с временем, местом, организатором
  и статусом ответа, кнопки «Принять / Под вопросом / Отклонить» с выбором «отправить ответ» или
  «не отправлять» (`AcceptItem` / `TentativelyAcceptItem` / `DeclineItem`). Отмены и ответы
  участников тоже распознаются по классу письма.
- Вид «Месяц» (клавиша M): 6 недель, до 3 событий в ячейке и «ещё N», клик по дню — вид «День».
- Напоминания (`src-tauri/src/reminders.rs`): планировщик раз в 30 с по кэшу событий; панель с
  «Отложить 5 мин» и «Закрыть», тост Windows один на событие; состояние хранится в базе с
  привязкой к моменту напоминания, так что перенесённая встреча напоминает заново.
- Из консоли: `aiowa calendar-create`, `calendar-update`, `calendar-delete`, `calendar-check`
  (полный цикл проверки на сервере), `meeting-info --item-pk`.

## Мгновенные обновления и уведомления

`src-tauri/src/notify.rs` поверх канала OWA (`docs/protocol-owa-json.md` § 4 и § 5h). После первой
удачной синхронизации фоновая задача подписывается (`SubscribeToNotification`) на строки всех
синхронизируемых папок, новую почту, дерево папок и календарь и держит открытым поток
`/owa/ev.owa2`; цикл потока сервер закрывает примерно через 5 минут, клиент завершает его
`FinishNotificationRequest` и открывает следующий. Идентификаторы подписок постоянны на время
жизни процесса, поэтому повторная подписка в той же сессии не плодит дублей.

- По событиям строк папки синхронизируются только затронутые папки (дебаунс 1,5 с, очередь, если
  синхронизация уже идёт); изменение дерева — синхронизация папки или полный прогон.
- Новая непрочитанная почта — уведомление Windows (tauri-plugin-notification): не чаще одного в
  5 секунд, при лавине одна сводка «N новых писем». Переключатель в строке состояния (колокольчик),
  ключ `desktop.notify_toasts`.
- Заголовок окна «AIOWA (N)» и значок на панели задач показывают непрочитанные во «Входящих»;
  обновляются после синхронизации и после действий из окна.
- Индикатор канала в строке состояния: «мгновенные обновления» или «по таймеру»; при живом канале
  страховочная синхронизация по таймеру идёт раз в 10 минут вместо 2.
- Счётчик непрочитанных через подписку Unseen этот сервер не отдаёт (нужен Broker), поэтому число
  берётся из локальной базы.
- Из консоли: `aiowa notify --seconds N [--folders inbox,…]` печатает виды событий и счётчики.

## Мультивыбор, отмена, архив, папки

- **Мультивыбор** в списке бесед: Ctrl+клик, Shift+клик, Shift+↑/↓, Ctrl+A, Esc снимает; панель
  «Выбрано N» с массовыми действиями (прочитано, флаг, переместить, архив, удалить), контекстное
  меню и клавиши применяются ко всему выбору. Больше 200 бесед за раз не берётся.
- **Окно отмены** (`src-tauri/src/staged.rs`): удаление, перенос и архив применяются в базе
  сразу, а на сервер уходят через 6 секунд; строка в состоянии «Удалено: … · Отменить», Ctrl+Z.
  Новое действие отправляет предыдущее; при закрытии окна всё отложенное отправляется до выхода.
  Команды `items_stage` / `items_undo` / `items_commit`; отказ сервера после отправки приходит
  событием `write-failed`. Удаление навсегда остаётся с подтверждением и без отмены.
- **Архив**: клавиша E, кнопка на карточке и в меню; папка `archive` или «Архив» верхнего уровня,
  без неё окно предлагает создать.
- **Перетаскивание** бесед на папки дерева (одной или всего выбора); для этого в
  `tauri.conf.json` у окна выключен `dragDropEnabled`, иначе WebView2 перехватывает события.
- **Папки** (`src-tauri/src/folders.rs`): контекстное меню дерева и кнопка «+»: создать,
  переименовать (F2), удалить (в «Удалённые», из них — навсегда с подтверждением); служебные
  папки защищены, имя проверяется; после операции сверяется дерево (`SyncFolderHierarchy`).
  Из консоли: `aiowa folder-create`, `folder-rename`, `folder-delete`, `folder-check`.
- **Reply-To**: заголовок читается при загрузке тел (`message:ReplyTo`) и хранится как получатель
  вида 4; «Ответить» идёт на него, если он отличается от отправителя; карточка показывает
  «Ответ на: …».

## Адресная книга

`src-tauri/src/directory.rs` поверх справочника организации Exchange (§ 5l протокола).

- **Автодополнение получателей**: локальные подсказки из переписки сразу, через 300 мс после
  ввода двух символов — справочник (`FindPeople` по папке `directory`, при отказе
  `ResolveNames`) отдельным блоком «Справочник организации» с должностью. Ответы кэшируются в
  базе (`directory_people`, схема v5) и в памяти на 10 минут на запрос, так что набор не
  засыпает сервер запросами.
- **Карточка контакта**: по клику на имя отправителя или получателя в письме и из меню чипа в
  композере — должность, отдел, компания, офис, телефоны, счётчики переписки по локальной базе,
  «Написать письмо», «Найти письма», «Копировать адрес». Полная запись берётся `ResolveNames`.
- **Списки рассылки** помечаются в подсказках; раскрытие (`ExpandDL`) на этом сервере не
  реализовано, окно это запоминает (`desktop.expand_dl_unsupported`) и прячет «Развернуть».
- Журналы без персональных данных: только счётчики и коды.
- Из консоли: `aiowa directory [--query Q] [--resolve] [--expand first|АДРЕС]`.

## Горячие клавиши

Таблица клавиш — `src/lib/hotkeys.ts`. Глобальные клавиши слушает один обработчик `App.onKeydown`
(сопоставление — `matchHotkey`, клавиши календаря выполняет `CalendarView.hotkey`); клавиши,
которые компоненты ловят сами, записаны там же справочно. Подсказки на кнопках берутся из той же
таблицы (`hint`, `keysOf`), разделы ниже собраны по ней вручную. Буквы распознаются по коду
клавиши, поэтому работают и в русской раскладке.

- **Окна поверх.** Пока на экране окно или всплывающее окно — настройки, подпись, предпросмотр
  вложения, редактор встречи, карточка контакта, вопрос-подтверждение, выбор папки, контекстное
  меню, — клавиши действий над письмами и событиями не срабатывают ни из шапки, ни из списка,
  дерева папок, композера или сетки календаря. Esc, Tab, стрелки и Ctrl+Enter достаются только
  верхнему окну, и Esc закрывает его одно. F5, Ctrl+R и печать окна целиком гасятся всегда.
  Окно, оставшееся открытым в спрятанном разделе, клавиш не держит.
- **Поля ввода.** Клавиша с пометкой «вне полей ввода» в поле ввода, списке выбора и редакторе
  письма не действует: там работают обычные правка и отмена.
- **Браузерные клавиши WebView2 выключены** (`disable_browser_accelerator_keys` в `lib.rs`):
  F5 и Ctrl+R не перезагружают окно, даже когда фокус внутри PDF-предпросмотра (рамка с другого
  источника, её клавиш обработчики окна не видят). Но и масштаб Ctrl+плюс/минус, и поиск по
  странице Ctrl+F браузера (в том числе в PDF), и встроенная печать окна, и DevTools по F12
  недоступны; в `tauri dev` DevTools открываются через порт удалённой отладки
  (`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`). Клавиши приложения из
  таблиц ниже работают: настройка выключает действия браузера, а keydown по-прежнему приходит в окно.
- В мастере первого запуска этих клавиш нет: это отдельный режим, почтовое окно не создаётся.

Первая сборка скачивает NSIS и загрузчик WebView2 в кэш Tauri, нужен интернет.

Установщик:

- ставит приложение только для текущего пользователя в `%LOCALAPPDATA%\AIOWA`, права
  администратора не нужны; база лежит в подкаталогах того же каталога;
- говорит по-русски, ярлыки — в меню «Пуск» и, по выбору, на рабочем столе;
- несёт загрузчик WebView2: если среды нет (редко на Windows 10), ставит её тихо, это требует
  интернета;
- при удалении стирает только свои файлы: `aiowa-desktop.exe`, деинсталлятор и ярлыки.
  Флажок «удалить данные приложения» убирает профиль WebView2 (`%LOCALAPPDATA%\ru.aiowa.desktop`),
  но не почту: база и кэш вложений в `%LOCALAPPDATA%\AIOWA`, журналы, конфигурация
  `%APPDATA%\AIOWA\config.json` остаются. Пароль и учётную запись убирает «Забыть учётную
  запись» в настройках, базу — удаление каталога вручную.

Приложение запускается в одном экземпляре: повторный запуск поднимает уже открытое окно.
Установленное приложение и `tauri dev` под той же учётной записью Windows делят базу и
блокировку, поэтому перед `tauri dev` установленное приложение нужно закрыть, иначе окно
разработки сразу закроется и поднимет установленное.

### Иконка

Источник — `src-tauri/icons/source/aiowa.svg`: конверт и искра. Тот же знак рисует компонент
`Logo.svelte` в шапке окна и в мастере. После правки источника:

```powershell
Remove-Item -Recurse src-tauri/icons/android, src-tauri/icons/ios
```

### Подпись

Сборка вызывает `src-tauri/scripts/sign.ps1` для каждого исполняемого файла: приложения,
деинсталлятора и установщика. Сертификат в репозитории не хранится, его задают переменные
окружения:

| Переменная                 | Назначение                                                                 |
|----------------------------|----------------------------------------------------------------------------|
| `AIOWA_SIGN_THUMBPRINT`    | SHA1-отпечаток сертификата подписи кода в хранилище «Личное», в том числе на токене |
| `AIOWA_SIGN_PFX`           | Либо путь к `.pfx`; пароль — в `AIOWA_SIGN_PFX_PASSWORD`                    |
| `AIOWA_SIGN_TIMESTAMP_URL` | Сервер меток времени RFC 3161, по умолчанию `http://timestamp.digicert.com` |
| `AIOWA_SIGNTOOL`           | Путь к `signtool.exe`, если его нет в PATH и в Windows SDK                  |

Без этих переменных подпись пропускается, сборка проходит. Неподписанный установщик работает,
но SmartScreen и антивирус показывают «Неизвестный издатель». Для рабочих машин подойдёт
сертификат подписи кода от внутреннего центра сертификации организации: ему уже доверяют
компьютеры домена.

```powershell
$env:AIOWA_SIGN_THUMBPRINT = '<отпечаток>'
npx.cmd tauri build
Get-AuthenticodeSignature ..\..\target\release\bundle\nsis\*.exe
```

## Структура

- `src/App.svelte` — три панели, строка поиска и строка состояния; выбранная папка/беседа;
  автозапуск синхронизации и обновление списков после неё.
- `src/lib/components/` — `FolderTree`, `ConversationList` (виртуализация строк), `ReadingPane`,
  `MessageCard` (письмо в `iframe sandbox` с CSP), `SearchResults`, `StatusBar` (кнопка «Обновить»,
  ход, время последней синхронизации, ошибки).
- `src/lib/api.ts` — типы DTO, обёртки `invoke` над командами Tauri и подписка `onSyncProgress`.
- `src/tokens.css` — дизайн-токены (светлая/тёмная тема, Fluent-подобные).
- `src-tauri/src/lib.rs` — команды `account_info`, `folders`, `conversations`, `conversation`, `search`;
  очистка HTML через ammonia; выход из сессии OWA при закрытии.
- `src-tauri/src/sync.rs` — состояние синхронизации, транспорт OWA процесса, команды `sync_*`,
  событие `sync-progress`.
- `src-tauri/src/ondemand.rs` — команды `message_fetch`, `attachment_open`, `attachment_save_as`,
  `open_external`; замки по письму и вложению, таймауты, тексты ошибок.
- `src-tauri/src/preview.rs` — протокол `aiowa-att` и команда `attachment_preview_url`.
- `src-tauri/src/write.rs` — команды записи `items_*`, оптимистичное применение и откат, событие
  `items-changed`.
- `src/lib/components/FolderPicker.svelte`, `ContextMenu.svelte`, `ConfirmPopover.svelte` —
  всплывающие окна действий; `src/lib/actions.ts`, `src/lib/popover.ts` — их общая логика.

## Безопасность отображения писем

HTML письма очищается на стороне Rust (ammonia: без скриптов, обработчиков событий и
`javascript:`), затем показывается в `<iframe sandbox="allow-same-origin" srcdoc>` с
`Content-Security-Policy: default-src 'none'; img-src data:; style-src 'unsafe-inline'`.
Внешние картинки и шрифты не загружаются вообще; инлайновые картинки письма приходят из кэша
вложений как `data:`-URI, подстановка делается в Rust при очистке (`attribute_filter` ammonia).

## Безопасность окна

- **CSP окна** (`app.security.csp` в `tauri.conf.json`): скрипты только свои, стили свои и
  встроенные (Svelte), картинки — свои, `data:`, `blob:` и протокол вложений, сеть — только IPC
  Tauri и протокол вложений, без воркеров, `<object>`, `<base>` и отправки форм. Рамка письма
  наследует эту политику и добавляет свою, ещё строже. Tauri не подмешивает хэши в `style-src`
  (`dangerousDisableAssetCspModification`), иначе `'unsafe-inline'` перестал бы действовать.
  В `tauri dev` окно грузится с dev-сервера Vite, CSP окна там не действует; политику проверять
  на собранном приложении (`npx.cmd tauri build --no-bundle`), а CI проверяет компиляцию
  продакшн-контекста.
- **Навигация** (`navigation.rs`): главное окно не уходит со страницы приложения. Разрешены
  только `http://tauri.localhost` и `https://tauri.localhost` (без порта и без `user@`),
  `about:blank` и `about:srcdoc`, в разработке — источник dev-сервера (на других платформах —
  `tauri://localhost`). Проверяется главная рамка:
  на Windows wry вызывает обработчик навигации из `NavigationStarting`, переходы рамок письма,
  PDF-предпросмотра и печати туда не попадают, поэтому протокола вложений и IPC в списке нет.
  Остальные переходы отменяются и пишутся в журнал схемой и хостом, без полного адреса. Ссылки
  из писем открываются в браузере командой `open_external`. Страница собранного приложения
  грузится в окно один раз: повторная загрузка отменяется (запись «повторная загрузка окна
  отменена» в журнале), даже если её вызвала клавиша, до которой обработчики окна не дотянулись.
  В разработке перезагрузки с dev-сервера разрешены.
- **Браузерные клавиши WebView2** выключены: F5 и Ctrl+R не перезагружают окно и из
  PDF-предпросмотра (подробнее — «Горячие клавиши»).
- **Протокол вложений** `aiowa-att` разрешает чтение через `fetch` (CORS) только источнику
  самого окна; картинке и рамке PDF CORS не нужен. Отдаёт только файлы кэша своей учётной
  записи и только типы, которые окно показывает.
- **Один экземпляр**: второй запуск не создаёт окно и сессию OWA, а поднимает уже открытое окно.

## Сессия и пароль

- Пароль хранится в диспетчере учётных данных Windows (запись «AIOWA», DPAPI под учётной
  записью пользователя). В памяти — `SecretString`; наружу он выходит только в форму входа
  `auth.owa` и в диспетчер.
- Cookies сессии OWA живут только в памяти процесса (`reqwest` cookie jar) и на диск не пишутся.
  При выходе из приложения и после «Забыть учётную запись» выполняется `logoff.owa` транспорта
  процесса: сессия на сервере закрывается, лимит сессий на ящик не копится. Проверка входа в
  мастере открывает свою сессию и закрывает её сразу после запроса папок, при любом его исходе.
- `config.json` содержит только сервер, логин и настройки первого запуска, без пароля.
- В `localStorage` окна — только выбранная тема.

## Журналы

Файлы `%LOCALAPPDATA%\AIOWA\logs\aiowa.ГГГГ-ММ-ДД.log`, новый файл каждый день, хранятся
14 последних. Дата в имени файла и метки времени строк — UTC: по Москве файл меняется в 03:00.
Уровень задаёт `RUST_LOG` (по умолчанию `info`). В `tauri dev` те же строки идут
в консоль.

Политика содержания: в журнал не попадают темы, тексты и адреса писем, имена людей, имена
файлов вложений, пароли и cookies. Пишутся операции, счётчики, коды ответов, длины, ключи базы
(`item_pk`, `attachment_pk`), имена папок и сама учётная запись. Ошибки протокола при разборе
успешного ответа несут только структуру ключей JSON, без значений.
